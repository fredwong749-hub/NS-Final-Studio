# 一致性为什么差，以及工程修复计划

> 2026-10-30，项目方要求：先做工程修复，视频放到最后一步。
> 依据：这两天的实测与审计（docs/qa_laptop.md、docs/audit/*、golden/*）、短剧平台调研（docs/canvas-ui-spec-v2.md、research v6）、剧本文档的原设计（design md file.md：全局设定→拆解全局角色→拆解全局场景→分集故事板）。

## 一、和其它短剧系统相比，我们缺什么

| 成熟平台的做法（小云雀 / 可灵主体库 / 即梦 等） | 我们现在 |
|---|---|
| **先锁全局资产，再出分镜**：全局设定 → 角色（多角度 + 造型）→ 场景 → 才开始分集故事板 | 资产是边出首帧边补的：首帧已经出了 3 轮，林晚母版才在第 3 次定下（v1 否决 → CL_s0 → CM_s1） |
| **主体库绑定到每个镜头**：每镜固定引用同一组角色图、服装图、场景图 | 每镜只有文字 + 一张脸参考；服装、鞋、妆按文字随机生成；造型表（data/looks）没接进提示词 |
| **场景资产**：同一地点用同一张场景图 | 没有场景资产；每镜从零文生图，同一部电梯每镜长得都不一样 |
| **镜头接力**：下一镜从上一镜的画面延续（同场景） | 每镜独立生成，相邻镜头之间没有任何参照 |
| **身份模型**：角色 LoRA / 主体特征 | 林晚的图像 LoRA 和视频 LoRA 都还没训练完 |
| **首尾帧锁动作**：先定首帧和尾帧，再出视频 | 355/360 镜没有尾帧；视频只从首帧往下猜 |
| **一条流水线**：一个模型栈、一套参数 | 笔记本和 gpu3 各出一套首帧（不同模型、参数、参考图），画布显示的帧和视频用的帧对不上 |
| **先做样片、锁参数，再量产**（剧本《纠正器》也写了“微型测试 → PIPELINE_LOCKED → 量产”） | 没有锁过任何一集；规则一夜改了十几次（风格后缀、母版、妆容、穿搭、高跟、漆皮、脚趾甲……），不同时间出的帧按不同规则生成 |

## 二、一致性差的根因（按影响排序）

1. **没有“先锁资产、后出图”的顺序**：资产和规则一直在变，已出的帧来自不同版本，前后当然不一致。
2. **两条出图链并存**：笔记本与 gpu3 各自出首帧，参考图、模型、后缀都不同（已于今天统一到 gpu3，config/shot_ownership.json）。
3. **缺场景锁和镜头接力**：同一场景的服装、光线、布景、道具每镜重新随机。
4. **造型没有进提示词**：每集穿什么、哪双鞋、什么妆，只靠剧本零散文字；造型表 49/60 集待确认，也没接入编译。
5. **身份只靠单张参考 + 文字**：Turbo 在 CFG 1 下负面词无效，编辑参考会照抄姿势；身份 LoRA 未就绪。
6. **剧本文字与模型冲突**：角色锁里的身材词、“必须可见”的脚趾甲导致赤脚等；每次靠事后打补丁。
7. **没有尾帧**：图生视频只有首帧，动作和人物在 10 秒内漂移，造成很多视频失败。
8. **质检阈值不可靠**：裸露检测 v1 既误报（衣着男性）又漏报（两张真裸露被设为当前），已换 v3（本地视觉模型）。
9. **没有冻结点**：任何改动都没有版本号，无法知道一张图是按哪套规则出的。

## 三、修复计划（视频最后做）

> **以项目方已批准的方案为准**（与 gpu3 会话确认）：修 3 个 bug + 方案 A + 方案 D，详见 docs/research/h3_prompt_and_fl2v.md、docs/research/seedance_consistency.md、docs/consistency_impl.md。
> - bug 1：H3 FL2VA 提示词改官方格式（对齐句、英文正文、`<d>` 内才用中文）；bug 2：首尾帧都预裁到 768×1344；bug 3：LightX2V 蒸馏与 shift 不匹配。
> - 方案 A：场景底板 + 三图编辑生成下一镜首帧，切镜处重新锚定，视频闸门（关键帧漂移 + 镜内身份）。
> - 方案 D：每镜人物状态时间线。
> 分工：**gpu3 负责渲染侧**（3 个 bug、场景底板、三图编辑、衔接与视频闸门、ep01 验证）；**笔记本（fredw-d9）负责**：画布就绪/衔接显示、`state_timeline.json`（由 data/looks + visual_bible + v3 生成，gpu3 读取）、v3 导入、规则版本化（T06），以及下表里 gpu3 方案没覆盖的项。
> 当前状态：gpu3 已暂停所有为他而骚的出帧与出视频（项目方：先训 LoRA，再出帧，最后视频）。

下表保留作为完整清单；其中由 gpu3 方案覆盖的项以 gpu3 实现为准。

| 阶段 | 内容 | 完成标准 | 负责 |
|---|---|---|---|
| **P0 冻结基线** | ①只保留一条出图链（gpu3，已定）；②一个编译器（共用 frame_spec/compiler）；③所有规则从 `config/visual_bible.toml` 读（T06），每次修改递增 `bible_version`，每个 take 记录它；④规则改动必须先写进 REQUIREMENTS / visual_bible 再执行 | 任意一张帧都能查到它用的规则版本；改规则后能自动列出受影响的镜头 | fredw-d9（T06）+ gpu3 同步 |
| **P1 全局资产锁** | 角色：林晚（CM_s1 已定）+ 男主候选（项目方挑）；造型：每集 A/B/C 由项目方在资产页确认（填完 49 集）；**场景资产**：按剧本地点建场景底板（写字楼大堂、电梯、出租屋各房间、顾沉家、专柜、车内……） | 项目方在资产页逐类确认，生成 `assets_locked` 版本 | fredw-d9 资产 + 项目方确认 |

| **P7 视频（最后）** | 只对就绪闸门全绿的镜头出视频；QA 通过才有 `_final` | qa.json pass | gpu3 + 后期 |
