# ep02 成片失败：自动检测结果（fredw-92，2026-10-31）

项目方原话：“ep02 整集失败：1，视频不连贯，部分只显示图片；2，图生视频很多地方失败；3，声音有问题，嘴唇也没有和声音同步；4，你启动自动图片检测，看看 bugs 在哪里。”

检测脚本：scratchpad `qc_ep02.py`（逐帧运动量：相邻帧 96×168 灰度平均差；音频 RMS），结果 `data/ab/qc_ep02/`。

**根因（证据强）**：静止的镜头全部是“首帧和尾帧几乎一样”（平均差约 5）；首尾差大的（S1 / S5 / S11）都有动作。尾帧是用 Image Edit 从定稿首帧改出来的“动作结束瞬间”，改动太小 → H3 FL2VA 被两张几乎相同的关键帧夹住，只能出一段几乎不动的视频。所有镜头还普遍在结尾 0.8–3 s 定住（向尾帧“落定”）。

另外每镜都只用 Turbo 8 步 LoRA（official_turbo），蒸馏 LoRA 本身也会压低动作幅度（待对照实验确认）。

## 2. “图生视频失败”

夜里视频任务 12 个完成、4 个失败；4 个失败都是 gpu36 存版本的旧 API 问题（已修）。所以“失败”主要不是报错，而是上面这种**跑成功但画面不动**的镜头——系统没有任何检测把它拦下来，自动定稿和合成都照常通过。

## 3. 声音 / 嘴型不同步

**根因（代码设计）**：合成器 `services/post/ns_post/assemble.py` 把 H3 自己生成的、和嘴型同步的对白**压低 40 dB**，再在每镜开头 +0.3 s 叠一条 Kokoro TTS 配音（另一个声音、另一种节奏）。所以听到的是 TTS，嘴型是 H3 按自己那条对白动的 → 必然对不上；TTS 音色也偏机械。另：
- S8 内心独白 13.9 s 盖过 S9–S11；
- 每镜 H3 提示词里都有自己的 non_diegetic_music，各镜配乐不同，切镜时音乐跳变；整集 BGM 因此被跳过（实际静音）。

## 4. 修复方向
1. **出视频前检查**：首帧↔尾帧差太小 → 不出 / 提示“尾帧几乎没变化”；**出视频后检查**：运动量低于阈值 → 标“静止·不合格”，自动定稿与合成都不放行；画布上显示。
2. **静止镜头重出对照**（S7 / S4 / S2）：只给首帧（不给尾帧）/ 尾帧改动更大 / 不同基底，看哪种能动起来，由项目方挑。
3. **对白用 H3 原声**（嘴型同步）：合成器加“对白来源 = H3 原声”模式，TTS 只用于内心独白和 H3 原声识别错时的兜底；出 ep02 第二版对比。

## 6. QCV：自动运动质检（2026-10-31，已上线）

**做了什么**：
- **出片前**：提交视频时算定稿首帧 ↔ 定稿尾帧差（96×168 灰度平均差）。低于 10 时，响应和画布提示写“尾帧和首帧几乎一样，视频大概率不动”。只提示，不拦项目方自己点的出片。
- **出片后**：每版视频算运动量，写在 take.qc.motion。画布在审片行视频格、精修大格、版本链上显示角标，悬停看数字。
- **整集出片**：auto_lock 不自动定稿“静止·不合格”的视频（该格 failed，原因写“需重出或项目方审片”）。以前出的、不合格且项目方没审片通过的视频，重出一次。
- **合成器**：timeline warnings 列出不合格 / 提示的镜头。
- **补质检**：`POST /api/qc/motion/backfill?episode=ep02`，或 `python -m ns_render.motion_qc --episode ep02`。ep02 已补完，结果在 `data/ab/qc_ep02/motion_backfill_ep02.txt`。

**阈值**（`config/render_quality.json` motion_qc 可改）：
- 帧差指 96×168 灰度相邻帧平均差，单位 0–255。差低于 0.35 的帧算静止帧。
- **不合格**：满足以下任一条件。
  - 平均帧差 < 0.5、p90 < 0.9、静止帧 ≥ 50%，三条同时成立；
  - 静止帧 ≥ 90%。
- **动作偏弱**：平均帧差 < 1.0。
- **结尾 / 开头定住**：连续静止 ≥ 1.0 s / 1.5 s。

**校准**（ep02 现有 26 个视频版本）：
| 组 | 平均帧差 | 静止帧 | 首尾帧差 | 判定 |
|---|---|---|---|---|
| S1（正常） | 1.6–3.7 | 15–23% | 33 | 通过 |
| S2/S3/S4/S6/S7/S10（静止） | 0.15–0.32 | 56–95% | 4.2–6.8 | 全部不合格 |
| S9、S11、S5 | 0.8–2.8 | 24–82% | 13–48 | 提示（偏弱 / 结尾定住） |
| S8 v2 | 0.40 | 48.5% | 5.0 | 提示（偏弱 + 结尾定住 1.6 s）——边界 |

当前视频判定：S2/S3/S4/S6/S7/S10 不合格，S5/S8/S9/S11 提示，S1 通过。与 §1 的人工判断一致。

“静止帧 ≥ 50%”这一条是看完对照实验后加的。S4 只给首帧的版本一直在小幅动（静止帧 38%），不算“只显示图片”，只算偏弱。

## MOT：卡顿 / 慢 / 脚重影（2026-10-31，fredw-92 派）

工具：`tools/motion_judder.py`（J4 每 4 帧一顿 + 显著性、光流节奏、jerk、下半身鬼影比）、`tools/ab_motion_fix.py`（同 seed / 同定稿首帧 / 同提示词正文，配方组合，gpu33 道同一次采样再用 fp16 VAE 解码一份）、`tools/ab_motion_fetch.py`、`tools/ab_motion_compare.py`（并排 mp4、腿部 0.5× 慢放、腿部条带）、`tools/dejudder.py`（后期去抖）。结果全在 `data/ab/motion_fix/`，汇总 `data/ab/motion_fix/best/metrics.md`。

### 原因（证据）
1. **卡顿 = H3 生成的 latent 本身“每 4 帧一顿”**：一个 latent 管 4 帧，跨 latent 那一次的变化约是 latent 内的 1.5–1.7 倍（S1 现行 J4 1.34，z 3.6；光流 J4 1.47，z 4.9）。
   - **不是 VAE**：同一次采样用 int8 / fp16 两个 VAE 解码，指标逐项相同；VAE 往返测试（平滑平移 → 编码 → 解码）J4 1.003，和原片一样平滑。所以换 fp16 VAE 没用（只多 2 GB 显存），不改。
   - 不只是 Turbo：Pika Flex（首尾帧 / 只给首帧）、基模 30 步 + 首尾帧也都有（J4 1.42–1.45）。**只有“基模 24 步 + 只给首帧”没有**（J4 1.12，z 0.7）。
2. **脚重影 / 多腿 = 现行 Turbo 8 步 v1.1 在快动作时把两个姿态叠在一个 latent 里**：S1 第 76–92 帧（3.2–3.8 s），前脚变成两只半透明叠在一起的鞋（`data/ab/motion_fix/legs/S1_cur_f64-88_zoom.jpg`）。同 seed 换 Pika Flex、基模 24 / 30 步，脚都干净（`legs/S1_PIKA_F1_f64-100_zoom.jpg`、`legs/S1_B30_f60-102_zoom.jpg`、`legs/S1_B24_F1_f60-102_zoom.jpg`）。S5、S9 有脚入画，看条带图没有脚重影；其余 8 镜几乎不动或腿脚不入画。自动“鬼影比”分不开好坏，只能当筛查，最后靠条带图。
3. **慢 / 不连贯 = 6/11 镜几乎不动（首尾帧几乎一样，见上文 §1，QCV 在处理）+ Turbo 压低动作幅度**。播放速度没问题：H3 原生 24 fps（官方 README “Output frame rate 24 FPS”，帧数 17n+5），出片、合成全程 24 fps，没有任何拉长 / 变速。整集平均光流：S1 1.8 px/帧，其余 10 镜 0.1–1.0 px/帧。只给首帧后 S2 节奏 ×2.8（基模）/ ×4.9（Pika）。

### 能用的配方（推荐，项目方定）
- **A. 质量档（推荐默认）：基底 `official_base`（不挂加速 LoRA，基模 25 步，shift 12/3，euler/simple，cfg 1）+ 只给首帧**。S1：无 4 帧一顿、脚干净、动作自然；S2 动起来（×2.8）。代价：每镜约 2.5–3 倍时间（S1 8 s：41 min，现行约 13–16 min）。
- **B. 快档：Pika Flex + 只给首帧**（时间和现行一样，约 12–14 min）。脚干净、动作幅度最大（S2 ×4.9），但仍有 4 帧一顿 → 可加后期 `tools/dejudder.py`（光流插帧后按真实时间重排，J4 1.42 → 1.08，帧数 / 时长 / 音轨不变，约 3 min CPU / 镜；看图没发现插帧伪影，但还没接进合成器）。
- lin_wan_h3_v1_step250 @0.8：在 Pika + 只给首帧上对动作 / 卡顿没有影响（J4 1.45，节奏 1.22）；基模 + lin_wan 正在出（S1、S2），结果补在 best/。
- 加大出图尺寸：不做。3090 在 768×1344 已是 22.7 GB 峰值、最长 260 帧；H3 训练画布就是短边 768，2K 需要官方没开源的 Regenerate-2K。

### 新发现 / 剩下的问题
1. **只给首帧时，H3 会在镜头中间自己切到另一个画面**（这里叫“中途跳切”）。首轮 11 镜里有 4 镜出现：S2 在 1.25 s 换了场景；S4 在 1.0 s；S8 在 0.9 s；S11 在 2.3 s 切到手部特写。S4 换了 4 个种子才出到没有跳切的版本。这些提示词里都没有写切镜。为此 ns_render.motion_qc 加了检测：相邻帧差 ≥ 20 且 ≥ 15 倍中位数时，标“中途跳切 Ns”，判 warn。旧版里 S5 也测出一处，在 4.7 s。以后出片看到这个标签就换种子重出。
2. **S6**：基模出了两版，都是“静止·不合格”。按 fredw-92 的指示加出一版 Pika Flex + 只给首帧（take 7），运动从 0.08 升到 0.26 px/帧，去抖后 J4 1.13，ep02_v1 用的是这一版。项目方反馈过 Pika 偶尔会让脸部泛红，DIR 正在查原因，这一版还没处理，需要项目方审片时留意。基模的两版是 take 5、6，都在版本链里。
3. **“动作偏弱”仍有 7 镜**（S2/S3/S4/S6/S8/S9/S10）。这些镜头大多是近景对白。和旧版相比，运动都提高了 1.2–3 倍，结尾也不再定住。
4. **长镜头道 OOM**：S8 有 294 帧，在 gpu36:2（--novram）上用无 LoRA 的基模跑了两次，都在 int8_linear 处 OOM。挂一个强度 1e-4 的 LoRA 让它走 LoRA 补丁权重那条路，就能正常出片。这个做法已写进 official_base.long_patch_lora，并在 h3_video 里自动生效。
5. **出片时间**：3090 上每镜 158 帧约 31 min（gpu36 约 49 min），192 帧 52–63 min，S8（294 帧，novram）约 92 min。
6. **林晚视频 LoRA（lin_wan_h3_v1_step250 @0.8）这次没用**。原因有两个：gpu36 的三条道上没有这个文件；提交时 MOT 的 S1/S2 结果还没出来。之后补测了 S2：基模 24 步只给首帧时，加 LoRA 的运动是 0.66、J4 1.106，不加是 0.51、J4 1.13，没有变差。S1 的结果和身份效果还要等 MOT 看完再定。
