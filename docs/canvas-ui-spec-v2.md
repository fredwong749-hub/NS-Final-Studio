# NS-Final Studio 画布界面规范 v2（2026-10-30）

> 本版替代 canvas-ui-spec.md 的第 C 部分，对应 REQUIREMENTS E1、E2、E3、E5、E6。
> 已经核实过的结论直接复用 docs/canvas_research.md，这里只补那份文档没写的部分：各平台的**镜头卡、首尾帧、资产怎么挂到镜头上**，以及**规范本身**。
> 标 ⚠ 的条目，要么只有单一来源，要么是从文字描述推断出来的。各家的登录后界面都没有截到图。

## 0. 结论

1. 公开资料里，**没有哪个平台在镜头卡上同时并排放首帧和尾帧两个槽位**⚠。
   - 小云雀和即梦把首尾帧当作「截帧 → 资产库 → 下一镜引用」的衔接手段。
   - 可灵和海螺把首尾帧做成一种单独的生成模式。
   - 所以「每镜固定显示首帧、尾帧两个槽位」要我们自己设计。依据是项目方的硬性要求和 Seedance 的首尾帧提示规范。
2. 小云雀的分镜明确会显示**本镜出场角色的妆造**和**场景图**。即梦和可灵用 `@资产` 绑定。我们的卡片要把这些做成**图片**，不能像现在只显示「林晚·默认·D0」这样的文字。
3. 图和视频分两步出，提示词也分两段写（OiiOii、海螺、Seedance 指南都是这样）。卡片上要分别显示首帧提示词和视频提示词。
4. 我们现在的画布：359/360 个镜头没有尾帧；表情一栏全是「—」；卡片上看不到人物图和提示词；集视图下半屏是空的。

## 3. v2 规范

### 3.1 镜头卡（集视图，一行 6 张）

**尺寸**：中栏宽 = 1800 − 左栏 240 − 检查器 420 = 1140 px，所以每张卡 **180 px 宽**（间距 8 px）。窗口宽 ≥ 1440 时检查器可以收起（`\` 键），收起后每张卡 280 px。卡片高度跟着内容走，约 620 px，正好利用现在空着的下半屏。

```
┌ ep01-S3  10s  ●未审 ──────── ⋯ ┐ 身份行：镜号·时长·审核点·菜单
│┌─首帧──────┐┌─尾帧──────┐     │ 两个 9:16 槽位，各 86×153，并排
││  [img]    ││  [img]    │     │ 悬停首帧 150 ms 后播放视频
││ v3 ✓      ││ 目标·生成v1│     │ 角标：版本号、来源、状态
│└───────────┘└───────────┘     │
│ [脸]林晚 A·通勤 D6 │[脸]陈宇 默认│ 人物行：28 px 脸图 + 造型名 + D 状态
│ 衣[▫]鞋[▫]甲[▫]发[▫]         │ 单品缩略 20 px，缺图显示红边▫
│ 表情 眼神躲闪、咬唇、呼吸加快  │ 黄色「未标注」=缺
│ 镜头 近景·低机位·缓推 85mm     │ 景别·机位·运镜·焦段，各自解析
│ 剧本 林晚推开旋转门，高跟…(2行)│ img_note/动作原文
│ 💬林晚：第一天实习，别出错(1行) │ 对白 / 🎙旁白
│ 图 清晨写字楼旋转门，低机位…(2行)│ 首帧提示词（编译后，改过加「改」）
│ 视 handheld follow 轻微手持…(2行)│ 视频提示词
│ 首帧▮ 尾帧▮ 视频▯ 审核▯        │ 四格状态条
└────────────────────────────────┘
```

**字段规则**：

1. **首帧槽**：显示当前版本。角标有三种：`v3`、「过期」（只在本镜自己的输入变化时出现，见 3.5 的 stale 拆分）、「锁」。
2. **尾帧槽**：尾帧是**独立资产**，来源有四种，用角标标明：
   - 「生成」：图像模型从首帧编辑而来。
   - 「next」：用下一镜的首帧。
   - 「上传」。
   - 「视频抽帧」：实际尾帧。
   - 如果视频已经出了，而且实际尾帧和目标尾帧不是同一张：槽位右下角叠一张 24 px 的「实际」小图；点一下打开接缝对比。
3. **人物行**：本镜出场的每个角色占一行。
   - 内容依次为：脸图（plates/front 裁出的头像）、造型字母和名称、D 状态。
   - 第二行是该造型用到的单品小图，顺序固定：衣、鞋、甲、发、妆、饰。
   - 有本镜覆盖时描边并标「改」；和上一镜不同时，左边加一条竖线，表示换装点。
   - 点脸图会跳到资产页，并定位到该角色的该造型。
4. **表情 / 镜头**：
   - 来自 `edit` 的值显示为普通文字。
   - 来自编译器自动解析的值显示为灰色斜体。
   - 两者都没有时显示黄色「未标注」，点一下就地编辑。
5. **剧本 / 对白 / 两段提示词**：都用 `line-clamp`，悬停显示全文，双击打开检查器并定位到对应字段。
6. **密度切换**（顶栏 `D` 键）：
   - 紧凑：只显示两个帧槽、人物行、状态条，约 280 px，用于总览审片。
   - 标准：显示上面全部字段。
   - 详细：提示词不截断。
   - 设置记在 localStorage。

**空状态**（每个槽位都要有占位和**就地动作**，不能只是一块空框）：

| 情况 | 显示 |
|---|---|
| 没有首帧 | 虚线 9:16 框，写「无首帧」，按钮〔生成首帧 I〕；正在排队或运行时显示进度条和「排队 #3」 |
| 没有尾帧，也没有设目标 | 虚线框，按钮〔生成尾帧〕；下拉菜单里有「用下一镜首帧」「上传」「从版本挑」 |
| 已设 next，但下一镜还没有首帧 | 尾帧槽显示下一镜的占位，写「等 S4 首帧」，按钮〔先出 S4 首帧〕 |
| 没有首帧时 | 〔生成尾帧〕置灰，提示「尾帧以首帧为底图，先出首帧」 |
| 角色没有脸图 | 灰色剪影加红点，提示「去资产页补 plates」 |
| 单品没有参考图 | 红边空方块，提示「只用文字描述」 |
| 成人路由的镜头 | 槽位照常显示，另加「本地」角标；未经项目方确认的，显示〔请求本地批跑〕（遵循 F2 规则） |

### 3.2 集视图和总览

- **集头**两行：
  - 第一行：集号、标题、梗概（可展开）、审核 x/6、〔整集出首帧〕〔整集出尾帧〕〔整集出视频〕〔串播〕。
  - 第二行：本集造型条，每个角色显示「脸图 + 造型字母 + 缩略图」，点击后高亮该角色在 6 张卡上的人物行。
- **卡间衔接**：卡与卡之间留 8 px 竖条。
  - 实线绿色：尾帧 = 下一镜首帧，且是最新的。
  - 黄色：下一镜首帧在视频之后换过，视频已过期。
  - 灰色虚线：没有衔接。
  - 点击竖条：底部抽屉打开**接缝对比**，内容是「S3 尾帧（目标 / 实际）| S4 首帧」，可以叠化、左右分屏，下面对照人物行。
- **列表模式**（`T` 键，参考 StudioBinder）：每镜一行，列包括：首帧、尾帧、人物、表情、景别、机位、运镜、对白、首帧提示词、视频提示词、状态。列可以开关，可以在单元格里直接编辑。适合逐字段批量校对。
- **总览**：每格放「首帧 | 尾帧」两张 9:16 小图（各 32 px 宽），下面是四格状态条；行头显示本集造型字母。成人镜头的格子显示进度色，不再显示空白。

### 3.3 检查器（420 px）

1. **固定头部**：镜号、审核状态、〔通过 A〕〔打回 X〕。
2. **帧对**：首帧、尾帧、视频三个标签，**并排两张 9:16（各 190×338）**。视频标签切换后，在同一位置播放。每个槽下面有：
   - 〔重新生成〕：原提示词换种子；
   - 〔修改后生成〕：先跳到对应提示词；
   - 〔上传〕；
   - 〔从版本挑〕。
3. **页签**（替代现在的 8 个折叠组）：
   - **剧本**：img_note、img_prompt、motion_prompt、sound、对白、旁白、extras、source_line。只读，并显示和编译结果的差异。
   - **首帧**：编译后的提示词（整段替换，diff 高亮）、负面词、dropped_triggers、种子和锁种、**本镜参考图组**（见 3.4.5）。
   - **尾帧**：
     - 来源单选：生成 / next / 上传 / 视频抽帧。
     - 生成模式下显示**尾帧提示词**（默认由编译器从 motion_prompt 的结束状态得出），以及底图 = 当前首帧版本。
     - 下面显示目标和实际的对比。
   - **视频**：
     - 运镜四个字段（景别、机位、运镜、焦段，每个都有下拉，也可以自由写）。
     - 表情（建议写 2–4 个可观察线索）。
     - 视频提示词：要预览**锚点声明**，比如「@图1 作为首帧…」「@图2 作为尾帧…」，再加上人物参考行。
     - 种子。
   - **人物**：每个角色一张小卡，包括：脸、造型 A/B/C 选择器、各个单品（值的来源：剧本 / 排期 / 覆盖）、D 状态、〔覆盖本镜〕〔恢复继承〕、conflicts 列表。
   - **版本**：首帧、尾帧、视频三条胶片条。勾两项后按 `C` 打开 A/B 对比，提示词逐行显示差异。
   - **审核**：原因码、备注、历史。
4. 所有写入仍然只走 `PUT /api/shots/{id}/edit` 和 looks 的 PUT 接口。规则沿用 v1 B5：串行写入、写回缓存、可撤销。

### 3.4 资产页（新的一级视图「资产」，快捷键 4；对应 E5、E6）

文件布局按资产会话交付的结构：
`assets/characters/<id>/{plates/, expressions/, items/<outfit|shoes|nails|hair|makeup>/, looks/}`，外加 `manifest.json`。manifest 里每条记录有 file、kind、prompt、seed、model、references、sha256。

```
┌左 200：角色列表（脸·名·造型数·缺图数）┬中：角色详情──────────────────────┬右 420：选中项检查器┐
│ 林晚 ●A B C  缺 3                  │ ① 定妆 plates：正 | 3/4 | 侧 | 背  │ 大图、manifest 字段 │
│ 陈宇 ●默认                         │ ② 表情表：中性 害羞 委屈 挑逗 …    │ prompt/seed/model   │
│ 顾琛 …                             │ ③ 单品  [衣][鞋][甲][发][妆][饰]  │ 被哪些造型/镜头引用  │
│                                     │    卡：特写图｜上身图·名称·标签·v2 │ 〔上传新版本〕〔设为│
│ [+ 角色]                            │ ④ 造型 A/B/C 组合器                │  主图〕〔重新生成〕  │
│                                     │ ⑤ 排期：角色 × 60 集               │                    │
└────────────────────────────────────┴───────────────────────────────────┴────────────────────┘
```

1. **定妆 plates**：一行 4 个槽位，背景为中性底，顺序固定：正、3/4、侧、背。
   - 缺哪个就显示虚线占位加〔上传〕〔生成〕。
   - 正面图就是镜头卡上的脸图来源。
2. **表情表**：网格，每格标表情名。
   - 镜头的「表情」字段可以从这里挑一格，挑中的图会作为参考图加入首帧的参考组（可选）。
3. **单品网格**：按类别分页签：衣、鞋、美甲、发型、妆、饰（饰对应现有的 accessory/LoRA 单品）。
   - 每张卡分两半：**特写（clean）**在左，**上身效果（worn）**在右。
   - 卡上显示：名称、标签（如 12cm、透明、漆皮）、版本号、LoRA trigger（如果有）、「被 N 个造型 / M 镜使用」。
   - 支持拖拽上传，也可以点〔上传〕。上传后会生成新版本，旧版本保留。
   - 打标签用逗号分隔文本输入。
4. **造型组合器 A/B/C**：
   - 每个造型一列，每个插槽一行（衣、鞋、甲、发、妆、饰、D 状态）。
   - 往单元格里拖单品卡就完成组合。
   - 列头显示 looks/ 下的预览图，以及〔生成预览〕。
   - 保存时返回 `affected_shots`，弹窗显示「影响 N 镜（M 镜已有视频）」，提供〔选中这些镜头〕。**不会自动重渲。**
5. **参考图组预览（E6）**：展示某一镜实际会送进模型的参考图，按顺序列出：
   - 脸 plate → 上身服装 → 鞋特写 → 美甲特写 → 发型 → 场景。
   - Qwen Image 2.1 最多 10 张；超出上限的显示为删除线，并注明「改用文字描述」。
   - 镜头检查器的「首帧」页签里也有同一个组件。
6. **排期**：角色 × 集的矩阵。
   - 每格显示造型字母，用色块区分；相同的值合并成一段；拖动色块边界可以改区间；也可以输入 `1-8, 17`。
   - 覆盖了单镜的集，在格子里加 ◆。
   - 点一格跳到该集的集视图。
   - 交互细节沿用 canvas_research §4.3③。

### 3.5 后端需要补的内容（只列接口契约，本文不改代码）

1. **尾帧成为独立资产**：
   - render 的 stage 增加 `"last"`，生成结果存为 takes，带 n、seed、prompt、`source: gen|next|upload|video`，并有自己的 active 版本。
   - `ShotEdit` 增加 `last_prompt`、`last_seed`、`last_source`。
   - 编译器输出 `last_prompt`（从 motion_prompt 的结束状态得出，⚠ 规则待定）。
   - 视频任务在「首尾帧模式」下读取 active 的 last 版本。
   - `_shot_summary` 增加以下字段：
     - `last_frame_target`：目标尾帧（URL 或 "next"）；
     - `last_frame_actual`：从视频抽出的实际尾帧；
     - `last_frame_source`：尾帧来源。
2. **summary 补齐卡片字段**：
   - `image_prompt`、`video_prompt`：编译后的全文，前端做截断。
   - `script_text`：img_note 加动作原文。
   - `camera`：拆成 `{size, angle, move, lens, source}`。
   - `expression`：`{text, source: edit|auto|none}`，编译器从 img/motion 原文里自动抽取。
   - `takes_count`：`{image, last, video}`。
   - 以上字段让卡片不必再为每一镜额外请求 `/api/shots/{id}`。
3. **按镜头的人物信息**：把 `/api/looks/shots/{id}` 的解析结果嵌进 summary，或者提供 `GET /api/looks/shots?episode=n` 批量接口。每个角色要带：
   - `face_url`；
   - `look_label`（A/B/C）；
   - 各插槽的 `thumb_url`；
   - `d_state`、`changed_from_prev`、`conflicts`。
4. **资产清单读取**：
   - `GET /api/assets/characters`：扫描每个角色的 manifest.json，返回 plates、expressions、items、looks。
   - `GET /api/assets/file?path=` 读取文件，限定在 assets/ 目录内。
   - `POST /api/assets/characters/{id}/import`：把 manifest 里的 items 登记到 `data/looks/wardrobe.json`。按 sha256 去重，不覆盖已有 id。
5. **wardrobe 单品扩展**：
   - `images: [{file, variant: clean|worn|front|3q|side|back, version, sha256}]`，替代现在的 `reference_images` 注册表 id（`REF-LW-01` 目前没有对应文件）。
   - 再加 `tags[]` 和 `version`。
   - SLOTS 已经有 nails、hair、makeup，不用新增。
   - 上传接口：`POST /api/looks/wardrobe/items/{id}/images`（multipart），返回 AffectedShots。
6. **Look 扩展**：
   - 增加 `label`（A/B/C）、`preview_image`、`version`。
   - schedule 不变，episodes → look_id。
   - 增加 `GET /api/looks/shots/{id}/refs`：返回送进模型的参考图组，带顺序和截断标记（对应 E6）。
7. **stale 拆分**：
   - 分成「本镜输入变化」（提示词、造型 hash、首帧）和「全局编译器升级」两类，后一类不在卡片上显示角标。
   - take 记录渲染时的 `look_hash`（`/api/looks/shots` 已经有 look_hash）。
8. **批量入队**：`/api/render-batch` 支持 stage=`last`，并支持「只跑缺失的」。
