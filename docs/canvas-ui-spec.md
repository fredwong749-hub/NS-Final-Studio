# NS-Final Studio 画布界面规范 v1（2026-10-30）

> 用途：M3 创作页的可施工规范。剧本和分镜离线写好后导入；画布用来管 60 集 × 6 镜，逐镜审首帧、尾帧、提示词、运镜、表情和对白，修改后重渲，并且每一镜都要标明用的是哪套造型。本文不含代码。⚠ = 未能从官方或可读来源核实。

**结论**
1. 中国的短剧平台都是「资产库 + 分集 / 片段轴 + 单镜提示语」三件套。自由节点画布只是辅助，用来修单张图。
2. 「多形象」是共识（小云雀的形象树、可灵的「服装与配饰」类主体），但没有一家在镜头卡上**显式标出这一镜用哪套造型**。这一点我们必须自己做。
3. 首尾帧都被当作两镜之间的局部手段，而且需要能看出它是否断了。
4. 版本管理普遍很弱（抽卡），我们的 takes 是优势。

## B. 旧 ns-studio UI 值得保留的做法

来源：`D:\NSFW Drama system\ns-studio\ui` 下的 design-v2.md、review-step3.md、v2-backlog.md，以及 ShotNode、Versions、LookTabs、useShotEdit、ShortcutsDialog。

1. **一个工作区**：左边树，中间主视图，右边属性面板，底边抽屉；顶栏显示全局状态（GPU / 队列）；Ctrl+K 命令面板；`?` 打开快捷键表。
2. **视觉 token**：深色高密度、单一强调色 + 四种状态色、等宽数字、CSS 变量。
3. **镜头卡**：9:16 缩略图，悬停 150 ms 后才加载视频；状态角标**叠放**（不互相覆盖）；锁、本地修改点、关键镜各用一个图标；底部是**媒体链四格条**（关键帧 → 视频 → 配音 → 评审，每格带状态色）；视频分「最新 / 已过期 / 缺失 / 被拦」四态。
4. **LOD + 共享缩略图缓存**（LRU，并发 4）。
5. **编辑语义**：逐字段提交；同一镜头的写入串行；成功后把返回值写回缓存；撤销 = 把旧值再写一次（同样经过后端校验）；被拒时把原因写在字段下面；字段正在输入时不被远端数据覆盖。
6. **结构化控件不得覆盖用户原文**：只替换生成的片段；解析不出来就显示「未设置」。
7. **版本胶片条**：单击只预览；「设为当前」要单独点，而且会把审核状态重置为「未审」；重生成先选原因（画面 / 表情 / 口型 / 连贯 / 比例 / 其他）。
8. **批量操作逐镜 try/catch**，最后汇总「镜 N：原因」，成功的部分合成一步撤销。
9. **造型绑定集号**：形象的「适用集号」用 `1, 3, 5-7` 这样的文本输入，写错就拒绝，不去猜。改了形象后提示「影响 N 镜」，由人决定重渲，不自动重渲。
10. 从 review-step3 得到的教训：
    - 不要每次选中都重建全部节点。
    - 键盘只用**一个分作用域的 keymap**：焦点在输入框或按钮上时不响应；忽略 `e.repeat`；空格在 keyup 时才播放。
    - 改了顺序后衔接要判为失效。
    - 100 集规模下单选不能出现超过 50 ms 的长任务。
11. **审核要防止误点**：通过前必须完整看过一遍；换了版本就清空已勾的确认项。

**不沿用**：React Flow 自由画布作为主视图（旧评审的问题大多出在这里）、对话式剧本阶段、G1/G2/G3 多级门。我们的剧本是离线导入的，只保留镜头级审核。

## C. 我们的画布规范

### C1 总体布局（≥1440 宽）

```
┌顶栏：项目 · 集选择器 ep03/60 · 视图切换[总览|集|造型] · 过滤 · 队列胶囊(运行1/排队7) · ?┐
├左栏 240──────┬中间主视图───────────────────────────────────┬右栏 420 检查器──┤
│ 集列表 60 行   │ 「集」视图：6 张镜头卡横排 + 集头                │ 选中镜头的分组面板 │
│ 每行：集号/标题 │ 「总览」视图：60×6 矩阵                          │ （C4）             │
│ 6 格进度点     │ 「造型」视图：角色 × 集 时间轴                    │                    │
│ D 状态 · 审核数 │                                                  │                    │
├──────────────┴底部抽屉（可收起）：版本胶片条 / 对比 / 任务队列────────────┴──────────────┤
```

- **主视图用固定网格，不用自由节点画布**。理由：结构固定（6 镜 × 10 s），网格可预测，也避开了旧版画布的性能问题。节点画布放到「后续」，只用于资产关系视图。
- **总览视图**：每集一行，S1–S6 六列，加一列集头。单元格是首帧缩略图加状态点。支持框选和行选；双击进入该集。用 LOD 和虚拟滚动，60 行要流畅。
- **集视图**：集头一行显示「ep03 · 标题 · 🔴高强度 · synopsis 折叠 · 本集造型条 · 审核 x/6 · 集操作」。下面是 6 张卡片横排，卡与卡之间有**衔接标记**（见 C6）。

### C2 镜头卡（宽约 200 px）

自上而下：

1. **首帧 / 尾帧并排**：首帧大图 9:16，悬停时播放当前视频；右下角嵌一张尾帧小图（当前视频抽出的 last_frame）。如果设了目标尾帧，小图带「目标」角标。
2. **角标**（叠放）：渲染中 / 排队、失败（读 errors.json）、已过期、已修改（edited）、成人路由（adult，标「本地」）、锁定。
3. **一行身份**：`ep03-S2` · 运镜（camera 简写）· 版本计数 `图3 视2`。
4. **造型条**（必有）：每个出镜角色一枚标签，格式为 `林晚 · 通勤 · D6`。
   - 继承自集计划：灰底。
   - 本镜覆盖：强调色描边加「改」字。
   - 和上一镜不同：左侧竖线，表示「换装点」。
   - 有冲突（缺参考图、剧本写的和计划不一致）：红色。
5. **表情**一行，加**对白首句**（说话人：台词，截断）；有旁白时带 🎙 标记。
6. **媒体链四格条**：首帧 → 视频 → 尾帧衔接 → 审核。
7. **审核徽标**：未审 / 通过 / 打回（带原因码）。

### C3 交互基本规则

- 单击选中，右栏打开检查器；Shift 选一段连续范围，Ctrl 逐个加选；在总览视图里可以框选。
- 双击卡片上的文字字段可以就地编辑（表情、运镜），其他字段在检查器里改。
- 右键菜单：渲染首帧 / 渲染视频、沿链重渲、复制编辑 / 粘贴编辑、设造型覆盖、锁定、通过 / 打回。

### C4 检查器分组（折叠面板，记住每组的展开状态）

1. **剧本原文（只读）**：img_note、img_prompt、motion_prompt、sound、对白、旁白、extras，以及来源行号（source_line）。
2. **首帧**：
   - 编译后的 image_prompt，可整段替换，以 diff 显示和原文的差异；还有 negative。
   - 显示 dropped_triggers 和 adult_reasons，只读。
   - 种子输入，加「锁种」开关。
   - 按钮〔渲染首帧〕。
3. **视频**：运镜（可以从常用列表选，也可以自由写）、表情、video_prompt（整段替换）、种子，按钮〔渲染视频〕。
4. **首尾帧**：
   - 首帧来源：本镜渲染（MVP）／上一镜尾帧（后续）。
   - 目标尾帧：无 / 下一镜首帧（`next`）/ 上传图片 / 从任意版本的帧中挑一张。
   - 并排显示「目标尾帧」和「实际尾帧」。
5. **造型**：
   - 每个角色一张小卡：套装、鞋、妆、发、装饰状态 D0–D10 / DN（含可见、隐藏、在匣）。
   - 显示值的来源：剧本 / 集计划 / 本镜覆盖。
   - 〔覆盖本镜〕〔恢复继承〕；旁边放参考图缩略图。
6. **版本**：首帧和视频两条胶片条，详见 C7。
7. **审核与备注**：状态、原因码、备注（ShotEdit.note）、历史记录。
8. **错误**：最近一次失败的原文，加〔重试〕。

所有写入都走 `PUT /api/shots/{id}/edit`，规则沿用 B5：串行、回写、撤销。

### C5 造型切换（每集 / 每镜）

**三层解析，优先级由低到高**：
1. 角色默认形象；
2. **集造型计划**（LookSchedule：集 → 每个角色的套装、鞋、妆、发、D 状态；从 `decor_schedule` 导入，含 overrides，例如 ep17 的 D4 礼服例外）；
3. **镜头覆盖**（同一集里换衣服、或某镜不可见）。

**界面**：
- 「造型」视图是角色 × 集的时间轴矩阵。相同的值合并成色带，在色带上拖动边界就能改区间；也可以输入 `1-8, 17` 这样的集号。
- 改动后顶部提示「影响 N 镜（其中 M 镜已有视频）」，提供〔选中这些镜头〕。**不会自动重渲**。
- 集头的**本集造型条**显示每个角色的集默认造型；点一下就把这一集的 6 张卡上该角色的标签全部高亮。
- 过滤器支持「D 状态 = D6」「造型 = 礼服」「有覆盖」「有冲突」。

**后端需要提供的数据**（目前缺少）：
- `GET /api/looks`：角色、套装 / 单品（插槽：套装、鞋、妆、发、指甲、装饰），每项的参考图 URL，以及 D 状态目录。
- `GET/PUT /api/look-schedule`：集 → 角色 → `{look_id, slots, d_state, visibility}`。
- `ShotEdit.appearance`：`{char: {look_id?, slots?, d_state?, visibility?}}`，即镜头覆盖。
- `_shot_summary` 增加 `appearance[]`：解析后的值，每项带 `source`（script / schedule / override）、`changed_from_prev`、`conflicts[]`。
- 每个 take 记下渲染时的**造型快照**和提示词哈希，用来判断「已过期」。

### C6 首尾帧链

现状：首帧是本镜渲染的结果；`edit.last_frame = "next"` 表示把**下一镜的首帧**当作本镜视频的目标尾帧（H3 FL2VA）。

- 卡片之间画一个衔接标记 `S2 ⟶ S3`：
  - 实线：S2 用 next，而且它的视频是按 S3 当前的首帧生成的。
  - 黄色：S3 的首帧在那之后换过，S2 的视频已过期。
  - 灰色：没有衔接。
- 点击衔接标记，底部抽屉打开**接缝对比**：S2 实际尾帧、S3 首帧、两者叠化或左右分屏，并显示造型标签是否一致。
- 上游有改动时，下游（这里是前一镜的视频）标为「已过期」。〔沿链重渲〕按依赖顺序入队：先出 S3 的首帧，再出 S2 的视频。
- 后续：「首帧 = 上一镜尾帧」作为第二种衔接，同一标记、反向箭头。

### C7 版本（take）

- 首帧和视频各一条胶片条，按 n 倒序；当前版本带强调色边框。每个缩略图标出 n、种子、耗时、时间，以及「旧造型 / 旧提示词」标记。
- 单击预览；按 Enter 或点〔设为当前〕调用 `POST …/takes/{stage}/{n}/activate`，同时把审核重置为「未审」。
- **对比**：选两个版本，按 `C` 打开 A/B 并排，视频同步播放，提示词逐行显示差异。
- 〔用此种子重渲〕会把种子写进 edit，然后排队。
- 换了当前首帧版本后，提示「视频是用旧首帧生成的」，卡片显示「已过期」。

### C8 批量操作

选中多镜（跨集也可以），或者用过滤器「全选结果」，然后：
- 渲染首帧 / 视频；沿链重渲；只重渲已过期的。
- 设造型覆盖；恢复继承。
- 粘贴编辑：选择要粘贴的字段（运镜、表情、负面词、种子策略）。
- 锁定 / 解锁；打回（共用一个原因）。

规则：
- 执行前显示一个确认框，列出镜数、预计任务数和会跳过的镜头（锁定的、缺首帧的），确认后才入队。
- 结果逐镜汇总。
- 批量通过只对「当前版本已完整播放过」的镜头生效。

### C9 审核状态

- **镜头**：`未审 → 通过 | 打回(原因码: 画面/表情/造型/连贯/口型/尾帧/其他 + 备注)`。打回后可以「锁定」。
  - 换版本或改编辑字段后自动回到「未审」。
  - 锁定的镜头不参与批量渲染。
- **集**：6 镜全部通过 = 本集通过。左栏集列表显示 `x/6`，过滤器可以筛「待审」「打回」。
- **审片模式**（`R` 键）：全屏 9:16 播放器，按 J / K 在镜头间移动，A 通过，X 打回（弹出原因选择），下一条自动跳到下一个未审镜头。旁边显示造型标签和参考图，用来对照造型。

### C10 快捷键（单一 keymap，焦点在输入框时失效，忽略按住重复）

| 键 | 作用 |
|---|---|

### C11 MVP 和后续的划分

**MVP（M3）**：
- 顶栏、左栏集列表；集视图 + 总览矩阵。
- 镜头卡：首尾帧、角标、身份行、造型条（先只读，解析 Shot.decor_state 和 decor_schedule）、表情、对白、媒体链、审核。
- 检查器分组 1–4、6–8。
- 胶片条，加「设为当前」。
- `next` 衔接标记，以及已过期判断。
- 批量渲染 / 锁定，结果汇总。
- 镜头审核状态和审片模式；完整的 keymap；任务队列抽屉（`/api/jobs`）。

**MVP 需要后端补的**：
- 审核状态和锁定字段；
- 批量入队接口；
- take 记录提示词哈希、造型快照，summary 返回 stale；
- `appearance` 解析结果；
- 用 SSE 或轮询推送任务进度。

**后续**：
