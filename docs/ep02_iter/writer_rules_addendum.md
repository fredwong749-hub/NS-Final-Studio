# 写作模型规则增补：让每个字段都能被系统准确实现（ARCH，2026-10-31）

**用途**：由总调度转交写作方。写作方决定是否采纳，以及怎么并入 `config/qwen_writer_system_prompt.txt` / `config/script_chat_rules.md`。
**范围**：本文件只讲**格式**和**可实现性**，也就是系统怎么读每个字段、怎么写才能被准确实现。不涉及剧情、台词、表演，也不评价内容。
**系统侧对应**：剧本 Markdown → `services/recipes/ns_recipes/spec_import.py` → Shot Spec（`packages/schema/ns_schema/shot_spec.py`）→ 配方引擎选配方并编译 ComfyUI 参数。缺字段时，系统按下面的规则号（SS-*）生成清单交还写作方，系统不代写。
**已接入**：§1–§11 的精简版已经作为“附录：系统可实现性规则 v1”（`rules_addendum_version: sysimpl-v1`），追加到写作模型每次都会加载的 `config/script_chat_rules.md` 末尾（`config/script_chat.json` 的 system_parts，不受附录预算影响），由 `tests/test_writer_rules_addendum.py` 保证。§12 未改，留给项目方决定。Shot Spec 的 `source.rules_version` 记录写作时的规则版本（例如 `rules_v2+sysimpl-v1`）。
**兼容**：新增的都是镜头里的普通 `**标签**：` 行。现有导入器不会因为这些行报错；旧剧本没有这些行时照常能出片，只是缺字段清单里会出现 warn。

---

## 1. 总原则

1. 一个字段只写一件事，用固定分隔符。系统按分隔符切分，不靠理解语义。
   - 条目之间用 `；`
   - 子项之间用 `｜`
   - 键值用 `=`
   - 时间写成 `0–2秒`（`–`、`-`、`~` 都认）
2. 屏幕方位一律从**观众看画面**的角度写：左、中、右，前、中、后。
3. 英文短语（EN）会被**逐字**拼进 H3 提示词，所以要写成完整的英文名词短语，不写人名、触发词、否定词或双引号。
4. 同一个人、同一个场景，在同一集里用的短语要逐字相同。系统用字符串比较判断“是不是同一个”。

## 2. 时长（**时长**，已有）

- 写 4–15 的整数秒，必须写（SS-D1，block）。
- 可实现性：系统按官方公式把秒数换成 17k+5 帧（6 秒 = 158 帧，8 秒 = 192 帧，12 秒 = 294 帧）。
  - 超过 260 帧（约 10.8 秒）的镜头只能派到唯一的长镜头道 gpu36:2，排队最长。
  - 剪辑规格（LEARNED_SPECS C）里单镜建议 ≤6 秒，超过会被剪成两刀（同素材推近 1.15×）。
  - 如果希望某段内容整段保留，就把它拆成 ≤6 秒的多个镜头。

## 3. 场景

### 3.1 地标（**地标**，新增，SS-S3 warn）

```
**地标**：<中文名>@<屏幕位置>｜EN=<english noun phrase>；<中文名>@<屏幕位置>｜EN=<…>
```

例（格式示意）：`**地标**：台灯@左上｜EN=a desk lamp；窗@右后｜EN=a night window`

- 屏幕位置写 左上 / 右三分之一 / 画面下方居中 这类词，和首帧构图一致。
- 用途有两处：
  - 重出第 2 次起，EN 名会进“锚点句”（官方 fallback 第 1 级）；
  - 同场连续镜头的地标对不上时，系统会提示（官方自检 4）。
- 同一场景连续两镜以上，地标必须原样继承。确实要变的，在 **衔接** 的“承：”里写明变化，或者标 `HARD CUT`。

### 3.2 光线（**光线**，新增，SS-S2 warn）

```
**光线**：主光=<方向+色温>｜补光=<…>｜轮廓光=<…>｜修正=<本镜相对场景表的改变，没有写 无>
```

- 场景表“光线”列是基线，本行写本镜的实际情况。同场下一镜的主光、补光、轮廓光变了而“修正”写的是“无”，系统会提示（SS-X2）。
- 可实现性：夜景镜头会自动叠加“夜景配方”（euler 采样，防止 I2V 变暗）。光线描述本身只通过 H3 正文生效，所以 H3 锚点句里的光源色温要和这一行用同一组词。

## 4. 景别与运镜

- **景别**：img 行第一个景别词就是本镜景别（SS-C1，block）。系统认这些词：极近特写、大特写、特写、中近景、近景、中景、中全景、全景、远景、大远景。别的说法系统认不出来。
- **运镜**：motion 行里的官方英文运镜词（push in / static shot …，SS-C2，block）决定镜头运动。
- 可选的新行，用来写幅度和速度：

```
**镜头运动**：<官方运镜词>｜幅度=<小/中/大>｜速度=<慢/正常/快>
```

- 可实现性：
  - 每镜只能有一个运镜（H3 单镜头）。
  - `static shot` 加上人物不动，几乎一定出“静止镜头”（ep02 有 7/11 镜静止）。想要画面在动，至少要有一个可见的身体动作（见 §6）。

## 5. 站位与朝向（**站位**，新增，SS-P2/P3 warn）

**人物** 行保持不变（`林晚（在画｜左｜中）`）。另起一行写朝向和起始姿势：

```
**站位**：<角色名>：<朝向>｜<起始姿势>；<角色名>：<朝向>｜<起始姿势>
```

- 朝向只用这些词：镜头、左、右、背对、侧左、侧右、侧。系统直接查表转成英文。
- 写“背对”的人，系统认为看不到脸，不做身份比对，也不要求身份参考图。
- 可实现性：
  - 重出时，锚点句写成 `…on the left side of the frame, in the midground, facing frame-right`。
  - 接力镜头里同一个人从左跑到右，系统会提示（SS-X4，ep02 S6→S7 林晚左右互换就是这种情况）。确实要换边，就标 `HARD CUT`。
- 每镜在画重要角色 ≤3 人（官方自检 3，SS-P6 block）；人物表里每个在画角色都要有 EN外貌短语（SS-P4 block）。

## 6. 动作分拍（**分拍**，新增；≥6 秒的镜头 SS-M1 warn，写了但有空隙 SS-M2 block）

```
**分拍**：0–2秒｜<可见动作>｜运镜=<…>｜位置=<…>｜声音=<…>｜交接=<…>；2–4秒｜<…>；4–6秒｜<…>
```

- 约 2 秒一段，从 0 写到镜长，中间不能有空档。只有“动作”一项必填，其余四项（官方五要素中的另外四个）可写可不写。
- 系统怎么用：
  - 分拍只存在 Shot Spec 里，**不会**原样进 H3。H3 只认连续英文，不认时间码。
  - 分拍用来做三件事：判断镜头类型（有位移 → “走动全身”配方）、做时间覆盖校验、在审片时和画面逐段对照。
  - 所以 H3 正文里也要把这些动作按顺序写成英文路径。
- 可实现性要点（来自 h3_comfy_expert §5，证据见原文）：
  1. **只给首帧**是现在的默认，尾帧不送进模型。motion 最后一个“——”之后写的结束状态，只会成为 H3 正文里的“结果”，不会被强制对齐，所以要写成正文里能自然到达的状态。
  2. 动作写**力度和速度**（例：`turns sharply`、`at fast speed`），比只写动词更容易动起来（lightx2v #58）。
  3. 远景、全身镜头里人脸很小，H3 容易画崩。这类镜头建议 5–6 秒、不说话。

## 7. 声音

### 7.1 台词时段（**台词时段**，新增；没写 SS-A2 warn，溢出 SS-A3 block）

```
**台词时段**：1=<起>–<止>秒；2=<起>–<止>秒
```

- 序号对应 **对白** 行里的第几句（从 1 开始）。
- 必须满足：止 ≤ 镜长 − 0.3 秒。超出就算“对白溢出”，这一镜直接判不通过（LEARNED_SPECS C）。
- 没写时，系统按每秒 4.5 字粗估，只给提示，不拦。

### 7.2 独白时段（**独白时段**，新增；溢出 SS-A4）

```
**独白时段**：<起>–<止>秒
```

- 🎙 独白仍然不进 H3（现有规则 H3-D6）。
- 独白时长不能超过镜长：ep02 S8 有 25.6 秒独白，塞进 12 秒的镜头后盖住了后面三镜。独白放不下时，要么拆到多个镜头，要么缩短。

### 7.3 H3 audio（已有，SS-A5 block）

- 必须写，1–4 句英文。原因是 H3 不会处理静音：没有环境声描述时，开头容易出现乱语和杂音（MiniMax HF #76）。

### 7.4 嘴型（**嘴型**，新增，可选）

```
**嘴型**：<角色名>=张；<角色名>=闭
```

- 不写也可以，系统默认：画内对白 = 张，画外 / 独白 = 闭。只有和默认不同时才需要写。

### 7.5 H3 正文里的声音格式（来自官方与社区，属于格式）

- `</d>` 前面要有句末标点（如 `。`）。缺了的话系统只提示（RL-D1），不改台词。
- 画外台词：`(S1) says in an off-screen voiceover: <d>[Chinese] …</d> while her lips remain completely closed.`
  - 这是官方逐字写法，系统会检查（RL-V1）。
  - 旧写法是单独写一句 `… lips remain closed.`，请改成紧跟在 `</d>` 后面的这句。
- 同一镜里在画但不说话的人，可以写 `silently`，减少嘴乱动（社区多人确认，系统待 E10 实测）。

## 8. 衔接（**衔接**，已有；新增 **下镜**、HARD CUT）

- `**衔接**：接力｜承：<延续项>`：接力镜头必须写“承：”（SS-L2 block）。如果视线、站位、道具或光线翻转，在“承：”里加 `HARD CUT`。
- 新增一行，写本镜结尾留给下一镜的状态（官方 Continuity Handoff 的后半句）：

```
**下镜**：<本镜结尾留给下一镜的姿势 / 道具位置 / 视线 / 声音桥>
```

- 新增一行，写上一镜在画、这一镜不在画的人去了哪里：

```
**出画**：<角色名>——<去向>｜<原因>
```

  例：`**出画**：顾沉——留在办公室｜本镜换场`。写了之后，系统不会把这个人的外貌和 LoRA 注入本镜（chain_audit A4）。

## 9. H3提示词（已有）

- 继续按现有四块格式写 FL2VA 原文。**系统会自动转换模式**：
  - 现在默认只给首帧（I2VA）。编译器会把第一行换成官方 I2VA 句，把 `Picture 1` 写成 `<Picture 1>`，并删掉引用 Picture 2 的收尾子句（官方 Case 2）。其余文字一个字都不改。
  - 走 Ref2VA（试验）时，编译器从正文和人物表 EN 短语确定性生成官方六段。
- 所以收尾子句 `… settles into … established by Picture 2 at the end of the shot.` 要**单独成一个子句**，前面的动作句写完整。这样子句被删掉后，正文仍然通顺。
- 锚点句（第一句）里，每个在画角色的人物表 EN外貌短语要**逐字**出现（RL-X1 warn）。原因有两个：
  - 重试时，锚点句也用这个短语；
  - Ref2VA 靠找到这个短语，才能在后面挂 `<Subject N>` 标签。
- 正文里出现的否定词（no / without …）会被提示（RL-N1）。官方的说法是：否定词会把被否定的概念写进画面。
- Ref2VA 的 `detailed_description` 官方建议 350–500 个英文词。走 Ref2VA 的镜头如果正文太短，系统会提示（RL-R2），是否加长由写作方决定。

## 10. 镜型（**镜型**，新增，可选）

```
**镜型**：<对白近景 / 走动全身 / 静态情绪 / 双人互动 / 长镜头 / 独白 / 空镜 / 环境>
```

- 不写时，系统按字段自动判断（规则见 `services/recipes/ns_recipes/selector.py`）。
- 只有自动判断和本意不同时才写，例如一个只露手部的特写想按“静态情绪”处理。试验配方（Ref2VA、两段式、Pika）写了也不会生效。

## 11. 尾帧曝光（**尾帧曝光**，新增，可选）

```
**尾帧曝光**：正常 / 暗 / 全黑
```

- 写“暗”或“全黑”的镜头，系统不会把画面变暗判为问题（近黑闸门关闭），也不会再往提示词里加“非纯黑”之类的后缀（chain_audit A2/C9）。

## 12. 现有规则中可能拖慢节奏的条目（只列位置和技术影响，改不改由写作方 / 项目方定）

EXPERT 发现，H3 本身偏慢动作（蒸馏 LoRA 会强制慢，训练数据也偏慢），这和规则里的“偏慢”可能叠加（h3_comfy_expert §5、§6，置信度：推断 / 低）。下面逐条列出：

| # | 位置 | 原文要点 | 进入哪里 | 技术影响 | 格式 / 技术建议（供写作方参考） |
|---|---|---|---|---|---|
| 1 | `config/script_chat_rules.md` 第 131 行（H3 正文规则，对应 lint H3-A11） | “动作量能在 N 秒内以**正常或偏慢速度**做完” | 写作方安排每镜的动作量 | 每镜安排的动作偏少，再叠加模型的慢动作倾向，就容易“静止 / 画面定住等台词”（ep02 v0 有 7/11 镜静止占比 ≥50%，10/11 镜结尾定住） | 改成“动作量按**正常速度**在 N 秒内做完，并留出最后约 1 秒仍在进行的动作”（推断；可用 E8 / 分拍验证） |
| 2 | `config/script_chat_rules_appendix.md` 第 67 行 | 林晚声线“**语速偏慢**、尾音软” | 人物表 VOICE 列 → H3 说话人首次出现的描述（逐字） | H3 按 `slow pace` 出声，台词时长变长，更容易对白溢出、需要拆镜 | 声线保留音色和音区，语速可以考虑写 `natural pace`，或者按镜在 `<d>` 外的描述里写语速（属于内容决定） |
| 3 | `docs/production_rules_v3.md` 第 114 行 | VOICE 要素示例里有“语速偏慢” | 写作方人物表模板 | 同第 2 条 | 同上 |
| 4 | ep02 人物表 VOICE 实际值 | 林晚 `soft slow pace`；顾沉 `measured slow pace` | 每句台词的说话人描述 | 两个主角都是 slow pace，对话镜整体变慢；v0 审片“一镜一句”的节奏感，部分可能来自这里（推断） | 同上 |
| 5 | `config/voices.json` lin_wan `speed 0.9` / `vo_speed 0.86`，gu_chen `speed 0.92` | TTS 放慢 | 只影响 TTS 独白和兜底（**系统侧**，不归写作方） | 独白更长，更容易盖住后面的镜头 | 系统侧另议（交总调度），这里只记录 |
| 6 | lint `H3-A10`（`script_chat_rules.md` 第 135 行）：camera 附近禁止 slowly / quickly | 运镜只用 `at slow speed` / `at fast speed` | H3 正文运镜 | 不影响节奏，只是写法限制；`at fast speed` 是允许的 | 需要快节奏时可以写 `at fast speed` |

## 13. 系统自动做、写作方不需要写的

- I2VA / FL2VA / Ref2VA 第一行，以及 S.SS 秒数（按实际帧数计算）。
- 采样参数、LoRA、分辨率、种子、去抖、校色。这些由配方决定，每个参数都有来源记录（`services/recipes/recipes/*.yaml`）。
- 身份参考图、场景底图、定稿首尾帧（资产侧）。
- 重出时的锚点句（只拼你写的 EN 短语和站位词）。

## 14. 校验与返修

- 运行 `.venv/Scripts/python.exe -m ns_recipes.cli specs --episode N`（PYTHONPATH 加 `services/recipes`）。它会生成 `data/recipes_out/epNN/missing.md`，逐镜列出缺字段：规则号、级别、交给谁、对应本文件小节。
- block：不能自动出片。warn：能出片，但画面不一定照写的实现。asset：交资产方（例如顾沉、陈宇缺身份参考图）。
- 总调度可以把 missing.md 原样作为【格式返修】请求转给写作方，只点名缺的字段，不涉及剧情。
