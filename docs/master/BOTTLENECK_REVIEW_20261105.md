## 2. 瓶颈（按影响排序）
1. **没活可派 → GPU 空转**（最大）：一集一个 producer 串着走；ep02–04 卡在资产（脸 / 场景等项目方挑）；ep05+ 剧本没写完；L1 换代没有自动入口（已过闸的旧版不重出）；producer 剧本缓存不刷新（KeyError 40 次）；按镜暂停 / runaway 冻结后无人释放。
2. **检测慢 + 误判多**：每张 228 s；看图只有 gpu36 GPU1 一个实例、经隧道（隧道常抖），笔记本 8870 显存被占满（OOM）；QB / Q9 / Q10 各自调模型、串行；误判（证据与结论矛盾）触发重出。
3. **视频单道**：按集分机，ep01 全在 gpu36:0；gpu36:1 被看图占、gpu36:2 坏卡；gpu33 三张卡不跑视频。
4. **改一处要走一整圈**：工人改码 → cut（本机七门 5–10 min）→ 部署被权限拦需项目方亲跑 → 受控重启（30 min 间隔）→ 才生效；默认 SSH 线路（直连 194relay）间歇断，部署失败重跑。
5. **总调度在环里**：每一步需要我看图 / 发命令 / 救火（今天 19 次人工驳回、多次解冻 / 重启）。

## 3. 处理（规则 + 代码，按顺序）
- **B1 检测提速**（目标：228 s → ≤60 s）：gpu33 上就地起看图实例（用空闲卡，不走隧道），Q9 / Q10 / QB 合并为一次看图调用（bundle 已有，扩到全部项），判词自洽检查（已做，待部署）。
- **B2 有活就派**：①换代入口：剧本 / 画风配置变了 → 按集自动重出（新版过闸前保留旧当前版）；②producer 导入稿 sha 变化自动重载（不再 KeyError）；③runaway 不计 code_error、retry 同时释放冻结；④按镜暂停到期自动恢复已有，补“解除暂停”命令。
- **B3 视频并行**：①分区让 ep01 这类单集也能按镜跨两台出（需 state / sync 合并，设计后做）；短期：video_boost（显存闸门）+ 看图迁出 gpu36 GPU1 后开。
- **B4 发版自动化**：发版 / 部署交给常驻 release_tick（W17 已建，按 release_request 自动 cut → deploy → 换代），项目方授权后不再每次亲跑；所有工具 SSH 统一走项目配置 -t / -hk 线路。
- **B5 资产不挡生产**：ep02+ 的脸 / 场景候选提前生成（已有），项目方一次在 #/queue 批量挑；或开代选（L-136，项目方定）。
- 规则（写进知识库）：画风 / 镜头相关的规则在 H4（镜头感）结论出来后补：背景必须有实景光源与纵深层次；首帧必须经 lens_sim（项目方选定后）。
