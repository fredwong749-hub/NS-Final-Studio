# 出图一致性 · 图片异常检测 · 集内连贯（总调度 fredw-2b，11-02 13:1x，L-118）

> 项目方原话（11-02 13:1x，节选）：“关于出图统一一致性的问题，我需要你从代码层解决一下。在分配任务时，需要有一个 master image agent 去进行图的分配，确保图片和提示词的一致性……问题散落在各个地方，存在一些不确定性”；“背景音乐……按每个镜头自动配……多个镜头拼在一起时，音乐就会出现断层和不连贯……应该在做完一个 episode 之后，确认没问题了再去配”；“image 那边做完之后，应该有一个 local 的 image detector……检测图片里有没有出现一些幻觉跟异常，比如多只手、多只脚，或者人物的位置是否合理……电梯里的男主角在镜子里会出现多个人头……如果这个能做得好，人类就不用参与太多审图了”；“以 episode 01 为例，01、06、07、08 拼在一起时，整个转场和场景都很生硬。是不是因为图片不统一，或者是在不同地方发布提示词有问题？……从代码架构层、infra 层、提示层来解决这个一致性的问题”。

## 0. 根因判断（总调度）
1. **每镜各自独立出图**：一个场景里的几个镜头，没有共同的“场景定稿”。灯光方向、色温、陈设位置、机位轴线、人物站位、服装细节都由每镜的提示词各自描述，模型每次重新想象，所以接起来像不同的地方、不同的时间。ep01 的 01 / 06 / 07 / 08 就是这样。
2. **提示词来源分散**：编译层有多处规则各自往提示词里加句子（style_suffix、融合句、灯光句、镜头句、视线句、F1 / F3 / K-REN-903……），参考图槽由 asset_refs、face_overrides、单品板、场景底图各自决定。没有一个地方能回答“这一镜最终用了什么、为什么”。
3. **检测只看单张**：V6 多肢、Q1 身份、Q1a 发色都是单张判定；“画面里的人头数 / 手数和 cast 对不上”“镜子里多出人头”“人物位置不合理”“和同场其它镜不一致”没有确定性检测。
4. **配乐按镜头配**：BGM 在镜头层面生成或挑选，集内拼接时就断层。

## 1. 代码架构层：一个“出图总编排”（IMGMASTER）
- **场景连续性计划（scene continuity plan，单一来源）**：每集每个场景先生成一份场景定稿 `data/pipeline/runs/<run>/continuity/epNN_<scene>.json`，内容：
  - 场景母版底图（scene master plate，先出一张无人或空镜定稿，后续各镜从它裁取局部作为参考，S 臂的“按景别裁过的局部场景底图”）；
  - 主光：方向、色温、光比、动机光源（一场只定一次，所有镜共用同一句）；
  - 空间：陈设清单和位置、机位轴线（180° 线）、人物站位和朝向（屏幕方向 screen direction）；
  - 每个在场人物本场的造型、饰品、发型状态（一场只定一次）；
  - 调色基准：场景定稿图的色彩直方图 / LUT，用于后期色彩匹配。
- **唯一编译入口**（SYSARCH 评审：**不新起 compile_shot**，而是把现有唯一出图作业 services/agent/ns_agent/frame_job.compile_frame / build_first / build_last（K-REN-134，首尾帧只走 ns_render.unified_frame）改造成分段编译——否则会多出第二个“唯一入口”）：所有首帧 / 尾帧 / 编辑器作业（EDITOR_INTEGRATION 附录 A3 的 submit-interactive 也一样）都走它，按固定顺序拼段：
  `[景别·镜头] [场景连续性块（来自 continuity，整场相同）] [人物块（来自人物卡 + 本场造型）] [本镜动作 / 表演] [约束句]`
  其它规则（F1 / F3 / K-REN-903、融合、灯光、视线）只能通过“改写某一段”的插件接口介入，不许再直接往提示词里追加。每个作业都落一份 `compile_trace`：每一段来自哪条规则、哪个文件、哪个版本。
  **插件接口怎么防止规则再次散落（SYSARCH 评审）**：
  1. 插件登记表只有一份：`config/compile/plugins.yaml`（人写的配置），每条 = `{id, segment, rule_id, order, enabled}`；`segment` 只能是上面五段之一，`rule_id` 必须是 knowledge 里存在且带 check 的规则（G1：每个判断有 decider 和 check）。编译时遇到未登记插件 / 段名不对 / 规则不存在 → 报错（失败关闭），不跳过。
  2. 插件签名固定：`(segment_text, shot, continuity) -> segment_text`，只能返回本段的新文本，拿不到也改不了别的段和最终提示词；参考图槽不归插件，只归 IMGMASTER 的统一分配函数。
  3. arch_scan 新增一项“提示词旁路”：编译模块以外的代码对提示词字段做 `+=` / 拼接 / `.append`（prompt、img_prompt、text 等字段名）= 退化；现有散落处进基线，只许减。新增规则想改提示词只能加插件。
  4. compile_trace 随 take 落账（take 记录里 `compile_trace` 指向文件 + sha，进 #16 一本账；编辑器版本同样带），图像工坊 / 反馈后台按它回答“这一镜为什么长这样”。
- **参考图槽统一分配**：由 IMGMASTER 按固定优先级分配：身份脸 > 场景局部底图 > 本场造型单品板 > 其它；单一函数，单一配置，作业里记录用了哪几张、为什么。
- **同场一批出**：同一场景的镜头作为一批派到同一台主机（同一 ComfyUI、同一模型缓存、同一 seed 族），先出场景定稿，再出各镜。
- **continuity 文件是决策文件，按决策文件管（SYSARCH 评审）**：路径经 `tools/autopilot/runs.py` 的 run 目录取（不写死 series10_v1）；列入 tools/factory/decisions_guard.REQUIRED（本集有场景定稿时）和 deps 闭包（按 sha 推到服务器）——服务器缺这份或 sha 不对 → 拒派，不许静默按“没有连续性块”出图（Top15 #2 的教训）。

## 2. Infra 层
- 场景批次派单：producer 支持“场景批次”单位，分区按场景而不是按镜。
  **（SYSARCH 评审改写：分区单位保持“按集”，场景批次只是主机内的派单顺序）**现行分区就是按集（data/state/netfix/partition 的 images[host] = 集号），同一集的场景天然在同一台主机，“同场同主机”不需要改分区。分区单位同时是 #16 一本账的所有权和交接单位，改成按场景会让所有权粒度变细、交接次数成倍增加。定为：partition 仍按集；producer 在本机按“场景批次”排序派单（先 scene_plate、再同场各镜、同 seed 族）。**跨集共用的场景**（同一地点出现在几集、可能在两台主机）：场景母版底图按资产管理（EDITOR_INTEGRATION §3-4 的“采用为资产”路径，FACTORY 目标状态 + sha 推两台），各集的 continuity 文件只引用它，不各自出母版。
- 场景定稿也是资产：进 takes 账本（kind=scene_plate），需要人看时进“待你看”的审美挑选。
  （SYSARCH 评审）takes.json 现在是“每镜一份”，场景定稿没有镜头：放 `data/renders/<ep>/scene_<scene>/takes.json`，同样遵守 #16（所属主机单写者、seq、op_id、跨进程锁）；编辑器修场景定稿走附录 A 同一套命令（sid 用 `scene_<scene>`）。
- compile_trace 和 continuity 文件进 data/，变更触发 E24 签名失效（场景定稿一换，同场各镜自动重出）。
  （SYSARCH 评审）级联重出前先算影响镜数（同资产采用：先展示数量再执行）；**项目方已采用 / 加锁的镜（E23、编辑器 adopt）不自动重出**，只标“和新场景定稿不一致”进待你看，由人决定。
- 一致性指标进 RSI 线 1：同场跨镜的色温差、光向一致性、陈设一致性、身份一致性（Q1x）。

## 3. 提示层
- 场景连续性块用固定句式和固定词表（灯光词表、陈设词表），整场逐字相同；每镜只写“本镜的动作和机位”。
- 写作规则：剧本每场开头必须有场景定稿行（陈设、主光、站位），各镜不许和它矛盾（lint）；镜间转场写“衔接点”（视线、动作、声音）。
- 去掉各镜重复描述环境的句子，避免同一场景被描述成不同的样子。

## 4. 本地图片异常检测（detector，GPU 上跑，替代大部分人工审图）
（SYSARCH 评审：detector 跑在打分道上，不占生产出图道——在 config/factory/hosts.json 用 roles 标 `"detect"` / `"vlm"`（4-2 已收口，不另建道表），和 G6“本机打分常驻”合并成一个服务，不另起第二个打分进程。）
确定性优先，VLM 只做辅助：
- **人数 / 头数**：人物检测加人脸检测，计数必须等于本镜 cast 中露脸 / 入画的人数。镜面、玻璃反射区域先用分割找出来（镜子 / 电梯壁 / 窗），反射里的人头只允许是在场人物的镜像（位置和朝向对得上），否则判“多出人头”。
- **手 / 脚 / 肢体**：DWPose 全身关键点，每人手数 ≤ 2、脚数 ≤ 2，手指数量和长度比例在范围内；手部检测框数 ≤ 2 × 人数。
- **位置合理性**：人物脚底和地面接触（深度估计 + 关键点），人物和陈设没有穿插，人物尺度和透视一致，同场站位符合 continuity 的屏幕方向。
- **同场一致性 Q1x**：同场各镜的身份、造型、发型、灯光方向、色温、陈设和场景定稿比对。
- 判定代码化、阈值标定，用项目方的反馈和误拦样本做回归集；结果进契约，不过就自动按原因重出。

## 5. 后期：配乐和转场
- **BGM 改成集级**：一集剪辑锁定（镜头顺序、时长、视频都定稿；“锁定”是运行期状态，经 state_paths 记在 data/，由 DISTILL 编排器 flow 的阶段触发，不另起脚本轮询）之后，才按整集的情绪曲线生成或挑选一条连续 BGM，在场景切换处做交叉淡化；镜头级不再配 BGM。环境声按场景配一条连续底噪。
- **转场**：同场内用硬切加匹配剪辑（视线、动作衔接）；跨场用短淡化或声音先入（J-cut）；全集做统一调色（以场景定稿的 LUT 为基准，逐镜色彩匹配）。

## 8. SYSARCH 评审结论（11-02）
| 问题 | 结论 | 落在哪 |
|---|---|---|
| 唯一编译入口会不会变成第二个“唯一” | 改造现有 frame_job（K-REN-134），不新起 compile_shot；编辑器作业也走它 | §1 |
| 插件怎么防散落 | 单一登记表 config/compile/plugins.yaml + 固定签名只改本段 + 规则必须存在且带 check + 未登记即报错 + arch_scan“提示词旁路”棘轮 | §1 |
| 和 #16 一本账 | compile_trace 随 take 入账；scene_plate 用场景级 takes.json，同样单写者 + seq + op_id | §1、§2 |
| 和 EDITOR_INTEGRATION 附录 A | 编辑器作业走同一编译入口；修场景定稿走同一套命令；已采用 / 加锁的镜不被场景定稿级联覆盖 | §1、§2 |
| 和 state_paths | continuity / compile_trace 是 run 下的产物（经 runs.py 取目录）；剪辑锁定等运行期状态经 state_paths；插件登记表是人写配置留 config/ | §1、§5 |
| 场景批次 vs 按集分区 | 分区单位保持按集（也是一本账的所有权 / 交接单位），场景批次只是主机内排序；跨集共用场景的母版按资产走 FACTORY 目标状态 | §2 |
| 失败开放风险 | continuity 进 decisions_guard + deps 闭包，缺失或 sha 不符拒派 | §1 |
| 检测器占用 | 跑打分道（hosts.json roles），与 G6 打分常驻合并 | §4 |
| 新 loop 归属 | IMGMASTER 先登记 loops，编译层文件一个负责方 | §6 |
