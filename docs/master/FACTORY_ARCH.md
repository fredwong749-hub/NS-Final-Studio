# 服务器工厂架构（总调度 fredw-2b，11-02 01:1x，L-099）

> 项目方原话（11-02 01:1x）：“赶紧重构服务器那边的代码.我觉得服务器 GPU 那边的代码有很多问题,那边应该有个 local 库才对.这边的笔记本应该做一个简单的同步脚本任务,派到那边去生产就可以了.”

## 0. 为什么要重构（实测）
- 出图仍由笔记本 producer 经 6 条 ssh 隧道派到服务器 ComfyUI（K-OPS-N06 临时覆盖一直没交还）；每单要传 /object_info、参考图、取回大图，跳板一抖就丢单。
- 契约打分在笔记本发起：full_score 经 ssh + base64 传参考图到 gpu33；看图 VLM 经 LAN 代理到 gpu36:8870，单实例串行 → 打分 p50 646 s，积压闸卡死派单，GPU 空转。
- 多个 loop（NETFIX / WORKFLOW / DEBUG-RSI / VQAGATE / PROD）各自改一段服务器逻辑，没有单一负责人和单一代码树。

## 1. 目标：服务器是工厂，笔记本是控制台

```
笔记本（控制台）                           服务器 gpu33 / gpu36（工厂，各自独立闭环）
  剧本导入 → 作业表 ─┐                       ┌─ 本地库 library/（按 sha 存：设定图、裁切、参考板、单品图、LoRA、模型）
  决策 / 驳回 / hold ─┼─ sync push（小 JSON + 缺失的 sha）→ inbox/（作业表、control、rejects、hold）
  代码 sv-* tag ──────┘                       ├─ 本地 producer：只连 127.0.0.1 的 ComfyUI，派本机分区
                                             ├─ 本地打分：契约 Q1–Q9 + VLM（本机批处理服务），出完即打
  UI / 审片 ← merge_file ← puller（长连接、断点续传、sha 校验）← outbox/（成图、视频、分数、账本事件）
```

原则：
1. **生产路径上没有跨跳板的同步调用。** 服务器出图、打分、记账全在本机完成；跳板只用来异步传文件。跳板断一小时，服务器照常出图，恢复后 puller 补传。
2. **本地库按内容寻址。** 作业表只引用 sha / 逻辑名；服务器缺哪个 sha，sync 只补哪个。不再“推 90 分钟资产”。
3. **笔记本只做三件事：** push（作业表 / control / 缺失资产 / 代码版本）、pull（outbox）、UI 展示与决策。
4. **单一代码树、单一版本。** 服务器代码就是仓库同一份，经 system_version deploy 发 sv-* 版本，不在服务器上手改。
5. **单一负责人：** FACTORY loop 负责服务器运行时（producer、打分、库、outbox 写端）；NETFIX 只负责传输（隧道、puller、长连接）；WORKFLOW 只负责作业表生成与 push 清单；VQAGATE 负责打分算法（跑在服务器本机）。
6. **笔记本 laptop:0 是第三台工厂**，同一套代码，库和 outbox 在本机。

## 2. 迁移顺序（不停产）
1. gpu36：assets_ready=true（01:05）→ 立即交还服务器模式，验证本机闭环（出图 → 本机打分 → outbox → puller → UI）。
2. 打分搬到服务器本机（VLM 批处理服务 + full_score 常驻服务，参考图从本地库读）。
3. gpu33：同样流程交还。
4. 删除临时覆盖 K-OPS-N06 和笔记本隧道派单代码路径（先隔离，不删）。
5. 每一步过：test 全绿 + 真实 3 镜端到端 + GPU 利用率 ≥ 80%（按小时）。

## 3. 验收指标
- 服务器 GPU 平均利用率 ≥ 80%（看板按小时）。
- 每单出图 + 打分 p50 ≤ 2 分钟（服务器本机计时），回传延迟另计。
- 跳板断 30 分钟演练：服务器不丢单、不停产；恢复后 30 分钟内补传完。
