## 7. 怎么一起干活（不打架）

- **频道**：所有 Agent 在 `docs/master/CHANNEL.md` 末尾追加一行：`MM-DD HH:MM | 你的名字 | 做了什么 / 发现了什么`（JST，`TZ=JST-9 date`）。开工前读最后 50 行。
- **一个文件同一时间只一个 Agent 改**：开工前在 CHANNEL 写明要改哪些文件；看到别人正在改的文件先协调（问 PS-MASTER）。producer.py / resident_sync.py / owner_queue.py 是热点。
- **改代码的标准动作**：写单测 → `.venv/Scripts/python.exe -m pytest -q <相关测试>` → `.venv/Scripts/python.exe tools/qa/arch_scan.py --files <改动的 py> --check`（不能有退化：无超时子进程、非原子写 JSON、静默吞异常等都会被拦）→ 交给 PS-MASTER。
- **写 JSON 一律原子写**（tmp + `os.replace`），Windows 上 `os.replace` 要对 PermissionError 重试。
- **发版只由 PS-MASTER 做**：`ops/psmaster/cut_deploy.sh <清单> <标签>`（清单 = `path@blob`，blob 用 `git hash-object -w`）。七道闸门：语法、知识库、arch_scan 棘轮、看图回归、决定检查、决定同步、定向 pytest。过了自动推两台、核 sha、按版重启、开分支 + PR。
- **独立复审**：交付由另一个模型复审（写和审不同模型）；复审结论 SHIP / SHIP-WITH-FIXES / BLOCK。
- **服务器只读**：除非 PS-MASTER 明确派，Agent 不在服务器上写文件、不杀进程、不重启。
- **重启**：笔记本 API `ops/restart_api.ps1`；同步 `ops/restart_resident_sync.ps1`；资产 `ops/restart_autoflow.ps1`；服务器由发版自动重启。

## 9. 跟项目方沟通的方式（重要）

项目方 11-07 凌晨原话的意思：“跟你沟通很累，你从来不跟我深度交流，只给简单选择，很多是没上下文的选择，所以才有这么多混乱。”

所以：
- 不要甩字母选项。要他定的事，讲清四件：**发生了什么（用他看得见的东西说）→ 为什么要他定 → 每种做法的后果 → 你的建议和理由（含没把握的地方）**。
- 他可以用自然语言回；你照他的原话执行，并在记录里注明“项目方对话授权”。
- 只报里程碑和要他决定的事；数字要有出处；报“成片好了”之前自己先看完。
- 问题要系统自己先发现（自查 `tools/brain/invariants.py`），不能等他撞上。
