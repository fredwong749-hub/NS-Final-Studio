# 好莱坞级短剧总方案（总调度 fredw-2b，11-02 00:4x）

> 项目方原话：“作为 RSI，我应该要做什么我不太知道，但是你应该知道……我把所有的 GPU 资源都给你，系统、API 都给你了，但是目标很简单：我要全部系统化，出一个 Hollywood level 的、画面非常漂亮的短剧……我起码要达到 50 分，就是你给的那个分数，50 over 50。”

## 0. 诊断：现在离目标差在哪（都有实测出处）

| 关卡 | 现状 | 根因 |
|---|---|---|
| ① 生产稳定性 | 7 张服务器卡今晚多数时间空转；40 分钟只出 5 张图 | 跳板（单连接约 50 KB/s，握手 6–7 s）+ 我们自己的连接风暴 + 服务器 v7_lipsync 吃满 96 核 + 出图仍经笔记本隧道派 |
| ② 写作分 | HOLLYWOOD 10 集 36–42.5 / 50，8–9 项卡在 4 分 | 写作模型推理关闭；评审口径笼统（4→5 没有可核对标准）；“台词逐字不变”这条不变量直接卡死“潜台词 / 冲突 / 钩子”三项；单稿改写，没有多稿择优 |
| ③ 画面 | 出图项目方满意（S★ R0）；视频 Pika 有 4 帧一顿（已去抖）、坐→站外套漂移、男主口型弱 | 首帧决定大部分；视频侧缺“导演层”（运镜、转场、剪辑节奏）和成片级后期（调色统一、音效、配乐、放大） |
| ④ 衡量 | 只有剧本分和逐镜契约，没有“成片好不好看”的分 | 缺成片级评分，RSI 无法对整片迭代 |

## 1. 方案（按依赖顺序，四条线并行推进）

**A. 生产全上服务器（今晚，NETFIX + WORKFLOW + DEBUG-RSI）**
- 出图、看图、视频、合成全部在服务器本机闭环；笔记本只做控制台、推代码、看片。资产推齐后自动交还（已在做）。
- 连接：8 条常驻连接 + 闸门（已上线）；服务器脚本统一限线程。
- 目标：服务器 GPU 平均利用率 ≥ 80%（按小时统计，看板显示）。

**B. 写作冲 50 / 50（HOLLYWOOD + RSI）**
- 写作模型开推理（large-flash reasoning high，或 large-v2 长推理），每轮出 3 稿并行，评审择优（best-of-3），再做“专项精修”：钩子、转折、潜台词、结尾钩子各一遍，每遍只改一个维度。
- 评审改成**可核对清单**：每个维度 5 分 = 满足 5 条具体条件（例如“5 秒钩子 = 第一镜内出现可视化的危机或欲望 + 主角主动动作 + 问题未解”）。两个独立评审取平均，加第三个“刁钻评审”专找扣分点。
- 不变量放宽到项目方模板原话的红线：**剧情事实和人物设定不改**，台词允许为了潜台词重写（需项目方点头，见“需要决定”）。
- 目标：10 集每集 ≥ 48 / 50，最终 50 / 50；分数轨迹逐集可见。

**C. 成片级“导演 + 后期”层（新派 DIRECTOR loop）**
- 镜头语言：按剧本节拍自动定运镜 / 转场（J-cut / L-cut、动作接、视线接），写进镜头规格，编译器落到首帧和 Pika 提示词。
- 后期：整集统一调色（LUT 按场景 / 时段），音效层（脚步、门、环境），配乐按情绪节拍（项目方已定“整集统一 BGM”），去抖 + 放大到 1080 / 4K（SOP §12）。
- Pika 已知问题逐个收口：外套漂移（拆镜 / 尾帧）、口型（说话人不低头 + V7 只测台词段）。

**D. 成片评分与 RSI 闭环（VQAGATE + AUDIT）**
- 每集成片跑“好莱坞观感分”：画面（构图 / 光线 / 一致性）、表演（视线 / 表情 / 口型）、剪辑（节奏 / 连贯）、声音（对白清晰 / 配乐 / 音效），本地看图模型逐镜 + 整集，加确定性指标。
- 每轮找全局最低的维度，修系统（不是修单镜），发新系统版本（sv-*），重出受影响镜，重新打分。

## 2. 每轮 RSI 的固定动作（写进 ITERATION_PROTOCOL）
1. 量：GPU 利用率、出图/出片速度、剧本分、成片分、闸门拦截率。
2. 找：全局最低项 → 根因（G0 先扫已有部件）。
3. 修：改系统 + 规则 + check。
4. 验：小样 A/B → 亲审 → 上生产。
5. 发版：system_version cut + deploy + 推 GitHub。
6. 记：morning 报告 + 版本记录。

## 3. 需要项目方决定
1. 台词是否允许为潜台词重写（剧情事实和人物设定不变）。
2. 写作 API 预算（推理 + 多稿择优，10 集估计 $40–80）。
