## 4. 计划（按顺序；每阶段有通过标准，过了才进下一阶段）

### 阶段 0：测量（半天；不改生产）
- 0.1 **端到端计时**：ep01 一次完整重出（L2 版）逐段打点：编译 / 派单等待 / 出图 / 检测 / 重出 / 尾帧 / 视频排队 / 视频 / 超分 / 合成 / 同步，出瀑布图。
- 0.2 **出图服从度基准**（B3）与 **视频运镜服从度基准**（B2），用确定性指标（look_metrics、motion_qc 光流方向 / 幅度）+ 总调度亲看。
- 通过标准：知道“慢在哪一段、占多少”“哪个模型 / 档位 / 写法能出我们要的镜头”。

### 阶段 1：效率（1 天；改代码 + 运维）
- 1.1 部署已写好的：B1 看图提速（gpu33 本机实例 + 分发）、B2 换代 / 热重载 / 解冻、判词自洽检查。
- 1.2 **视频按镜跨两台并行**（不再按集分机）：gpu33 三张卡也跑 H3（先核 gpu33 模型与显存）。
- 1.3 **一键编排**：`episode_run --ep 1`：剧本导入 → 探针 → 换代 → 出图 → 视频 → 合成 → 拉回 → 对比页，全自动按阶段推进、超时 / 失败登记卡点，总调度只看报告。
- 1.4 **发版自动化**：release_tick（常驻）按发版请求自动 cut → deploy（需项目方授权一次）；SSH 统一走项目配置 -t / -hk。
- 通过标准：ep01 16 镜首帧 → 成片 ≤ 2 h，出图道占用 ≥ 50%，检测 ≤ 60 s / 张。

### 阶段 2：镜头感（1–2 天；按阶段 0 的数据定）
- 2.1 **提示词按模型重写**：编译器分“出图模板（Qwen-Image：机位 / 景别 / 焦段 / 景深置前、精简、去冗余）”与“视频模板（H3 官方写法：运镜 + 时间轴 + 动作）”；写手只写结构化字段，不直接写模型提示词。
- 2.2 **运镜词表扩展**：按 B2 基准结果，把 H3 真能执行的运镜（推 / 横移 / 弧 / 升降…）给项目方看样片后启用（L-129 是项目方的决定，需项目方点头）。
- 2.3 **出图档位**：若 35 步定稿档服从度明显更好，首帧改用定稿档（代价：出图 ~3–4×，靠阶段 1 的并行抵消）。
- 2.4 L2 分镜（coverage / 轴线 / 焦段）+ H4 lens_sim + 剪辑规则（动作点剪、J/L cut、节奏收紧不截动作中段）。
- 通过标准：总调度亲看五条全过；项目方看对比页点头。

### 阶段 3：ep01 定版
- 3.1 用阶段 1 的一键编排跑 ep01 L2 版 → 成片 → BGM 锁定（服务器补 V2 曲库）→ 对比页（v3 vs L2）。
- 3.2 项目方反馈 → 规则 → 再跑，直到项目方点“用这版”。
- 3.3 RETRO_ep01 v2：指标对比、规则清单；然后才开 ep02。

## 8. 阶段 0.2 出图服从度基准 B3（Fable，11-05；tools/research/adherence_img_ab.py → data/ab/adherence_img/、页 data/review_pages/adherence/img.html）

## 10. H4 镜头虚化结果（11-05，Fable；PS-MASTER 亲看 S13 / S4 A vs B）

| 横移 truck 左 / 右 | 动作强且稳定，但**方向反了**（亲看：写“左”机位向右，写“右”机位向左，前景环形灯穿出画面）；幅度 3–5× 目标；写“small”后几乎不动 |
| 环绕 arc | 官方写法出了**真环绕**（侧脸 → 正脸，背景大换），方向同样反；幅度大 |
| 双人中景 S4 | 横移 / 环绕都被做成“后拉 + 升”，不受控 |
| camctl（ControlNet 轨迹） | 0 / 0.5，不可用 |
| FL2VA 首尾帧构图差 | 0.5–1.0，最稳（一致性 0.98）但幅度小、偏推 |
| 基模 24 步 | 横移 / 环绕方向对（1.0），但慢且一致性低（0.64–0.70） |
结论：①H3 不只会推近——官方写法下升 / 横移 / 环绕都能做，**编译器写法是主要病根**；②横移 / 环绕需方向词反写（或改写为“画面内容向 X 移动”）+ 幅度用中档词校准，再小样复测；③双人镜只用推 / 拉 / 固定 / 手持；④启用新运镜需项目方改 L-129（不触 L-088：全部仍是 Pika/H3）。

## 11. 视频按镜分片（阶段 1.2，CODER-VS，11-05；默认关，未部署）

**核实（只读）**：gpu33 已有 Pika 变体全套权重——`minimax_h3_fl2va_pruned_int8_convrot`（20 GB）、`qwen3vl_32b_minimax_h3_nvfp4_awq`（15 GB）、视频 VAE int8（3 GB）、音频 VAE fp32、`pika_h3_flex_fl2va_comfy_bf16` LoRA（1.9 GB）；ComfyUI 与 gpu36 同参数（`--reserve-vram 1`）。**无需下载。** 显存：gpu33:0/1 各驻留 12–13 GB 出图模型（同进程 ComfyUI 会换出，与 gpu36:0 同机制，视频时 ~17.6 GB）→ 可跑；**gpu33:3 不派**（看图 :8870 约 6.7 GB + `--reserve-vram 9`，20 GB DiT 放不下）。gpu36:1 另有看图，仍走 video_boost 的 vram_gate，不在本节范围。

**现状**：`hosts.json`（由 partition 生成）按集定主机 → `build_jobs` 给每镜写 `host` → vidgen Runner 只出 `host==本机` 的镜 → 状态是 `state_<host>.json`（一台一份）→ night 在 owner 台 `ep_resolved` / `finalize` 合成。两台 night 各自跑在服务器上（`OFFLINE_SELF`），互不信任。

**设计（不要租约文件、不要互相通信）**：
1. 分片表 = 纯函数 `video_shard.plan(配置, 本集全部镜+时长)`：显式 `map` 优先，其余按“时长降序、负载/权重最小的台先拿”贪心；确定性，两台各算得到同一张表。配置 `config/pipeline/video_shard.json`（`enabled:false` 默认关；示例 ep01：owner gpu36，权重 gpu36:1 / gpu33:2 = 两台可用道数比 → 16 镜 5 / 11）。随发版到两台。
2. `build_jobs` 对分片集每镜 `host` = 分片结果（owner 仍是 hosts.json 里那台）。vidgen 现有过滤即保证**两台出的镜互不相交**；`state_<host>.json` 本来就是各台独写，**不会互相覆盖**，无需合并写。
3. night：分片集在 helper 台也派（`_eps_on`）、helper 挂 `exclude_lanes`（gpu33:3）；helper 台 night 标 `shard_helper`，只出镜不合成；owner 台用 `ep_shots()` = `merged_shots()`（只读合并各台 state）算 `ep_resolved` / `ep_sig` / `finalize`，`vidgen proxies` 与 `episode_report` 同样读合并视图。helper state 没送到 = 那些镜算“没出”，owner **等**，不会拿缺镜合成。
4. 数据通路（服务器互不信任，一律经笔记本）：`tools/series10_video/shard_relay.py`（笔记本跑，`--loop` 每 120 s）：helper →（笔记本）→ owner，只送 `state_<helper>.json`、入选版本原片 `clips/*.mp4`、`scores/<镜>__*.json`，按大小/mtime 增量、成功后才记标记，走 rssh 主连接（deploy.ssh）。登记 takes 仍走 `register_takes` → `P.mutate_takes`（有锁），不手写 JSON。
5. 关 = 原行为：`enabled:false` / 没配 / 一台 / owner 不在分片台 → `plan_all` 返回 {}，`_eps_on` / `_shard_hold` / `ep_shots` 全部退回原写法（tests/test_video_shard.py 钉住）。

**预期**：ep01 16 镜 × ~406 s：gpu36:0 约 5 镜 ≈ 34 min，gpu33:0/1 两道约 11 镜 ≈ 37 min → 出片 ≈ 37 min（原 1.8 h，≈ 2.9×），另加 relay（11 条原片 2–4 MB，经笔记本）与合成。
