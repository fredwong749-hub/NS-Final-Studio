## 回来后（一条命令）
在 Git Bash 里执行：

    bash "/d/NS-Final Studio/ops/offline/resume_from_gpu33.sh"

它会依次：
1. 两台各跑 stop.sh，只停 run/*.pid 里自己的进程。
2. 把冻结后服务器上改过的文件拉到 data/_offline_pull/<host>/，再用 ops/offline/merge_pull.py 并回：
   - 只收负责该集那台的文件；
   - 新者为准，不删笔记本文件，覆盖前先备份到 data/_offline_pull/_backup/；
   - attempts.json 按对象合并，log.jsonl 和 night.log 追加，night_state.json 按集合并；
   - control.json、leases、pid 不拉回。
3. 笔记本 producer resume，再拉起 serve 和 night.py。
4. 跑 tools/qa/data_parity.py。

日志在 ops/logs/resume_from_gpu33.log。gpu36 上打分失败的帧不会当作通过：它们留在 pending，回来后由笔记本 producer 重打分。

## ⤴ 常驻模式（2026-11-01 17:00 起为默认，取代“离线才去服务器、回来再并回”；WORKFLOW，总调度 16:55，规则 K-OPS-W07）

- 生产在服务器跑：两台各跑本机负责集的 producer + night（同上表分集；gpu33 GPU2 坏卡永不用），目录仍是 /root/work/fredw/offline_20261101。
- 笔记本只做控制面：producer 已 `pause --by SERVER_RESIDENT`，night.py 已停；API / 前端 / 监控照常。
- 同步：`tools/autopilot/resident_sync.py`
  - `push <host>`：清单比对，只发不同 / 被截断的文件，分批 ≤ 24 MB，先解到临时目录再搬入，失败退避重试，发完复核补发；
  - `restart <host>`：服务器上跑 `ops/offline/resident_prep.py`（幂等补丁 + control.json）和 `ops/offline/resident_restart.sh`（只重启 producer / night）；
  - `pull <host>`：上次并回之后服务器改过的文件分批拉回、校验大小，交 `ops/offline/merge_pull.py`（截断文件不覆盖）；
  - `loop`：5 分钟一次服务器健康（每张卡利用率、队列、心跳；空闲但有活 ≥ 10 分钟写 data/qa/alerts.jsonl），20 分钟一次并回，代码有改动自动推 + 热重启。
- 回到笔记本跑（不推荐）：两台 `bash stop.sh`，`resident_sync.py pull` 两台，然后 `producer.py resume`、起 night.py。
- **跳板恢复后的一键动作**（总调度 17:4x）：`.venv/Scripts/python.exe tools/autopilot/resident_sync.py recover` —— ① 查两台常驻进程（fwd / producer / night）② 推最新代码 + 生产必需数据 ③ resident_prep 补丁 + resident_restart 热重启 ④ health ⑤ 服务器本机 Pika 冒烟一镜（gpu33:3，结果 data/autopilot/pika_smoke/ep01-S3__resident_gpu33.json）⑥ 起周期并回 loop。截至 17:48 跳板不通，**resident_restart.sh 在两台都还没执行过**。
