## H3 FL2VA research report (read-only; nothing on the machine was changed)

**Overall finding.** The strongest documented lever is the prompt format. The prompts are currently freeform Chinese. H3 expects an English structured prompt with dialogue inside `<d>` tags. That one change targets problem 2 (burned-in captions) directly and probably helps problem 3. For eyes, the fixes are face pixel size (768p, FaceRefine) and step count. Swapping the VAE will not help.

Note: in MiniMax's naming, a run with only a first frame is **I2VA**, served by the FL2VA checkpoint. It has its own alignment line, given below.

---

### 1. Eyes and faces break mid-motion

Ranked actions:
1. **Give faces more pixels.** Move to the native short edge of 768, which for 9:16 is **768x1344** ([MiniMax card](https://huggingface.co/MiniMaxAI/MiniMax-H3), [comfy docs](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-native)). The FaceRefine README says the problem tracks head size in the frame, not output resolution, so it "persists at 720p+" ([FaceRefine](https://github.com/Carasibana/ComfyUI-H3-FaceRefine)).
2. **FaceRefine settings** (from its README):
   - `crop_factor` 2.5 (useful range 2.0–3.0); canvas `auto_capped_768`.
   - Base denoise about 0.40. Because shift is 12, SDXL-style denoise values do not apply: 0.25 already gives sigma about 0.8.
   - Per-Frame Denoise multipliers 1.0 for small faces and 0.35 for large faces (thresholds 30/120 px).
   - SAM mask with feather 4–8, `mask_dilation` 16.
   - Optional 8-step lightx2v turbo at 1.0 with 8 steps. The step count must match the turbo LoRA you load.
   - Cost scales with canvas² × frames.
3. **Use more steps with turbo.** 6–8 steps instead of 4. At 4 steps, large or fast motion smears and ghosts ([Larryvrh Turbo](https://github.com/Larryvrh/ComfyUI-MiniMax-H3-Turbo), [seedance settings](https://www.seedance.tv/blog/best-minimax-h3-settings)). Larryvrh: turbo strength 1.0, raise to 1.05–1.2 for smear, lower to 0.8–0.95 for over-sharp grain.
4. **Sampler trial.** RES4LYF `res_2s` + `beta57` for "fast motion or distant faces." Single X post, **unverified** ([X](https://x.com/alexfredo87/status/2085467476431622435)). In the [HF wide-shot thread](https://huggingface.co/Comfy-Org/MiniMax-H3/discussions/30), one user suggests DDIM 8 steps + beta/beta57. That thread has no confirmed fix, and it reports that the **EasyCache node degrades quality**. Remove any cache or acceleration nodes during A/B tests.
5. **The VAE is not the cause.** The int8 VAE decode measures 67.7 dB against the exact path, while the VAE's own reconstruction floor is about 38 dB ([comfyui-wiki VAE](https://comfyui-wiki.com/en/news/2026-09-19-h3-video-vae-optimization), [Kijai #13](https://huggingface.co/Kijai/MiniMax-H3-experimental/discussions/13)). Moving to fp16 will not fix eyes.
6. **Quantisation.** W4A8 is reported slightly noisier than BF16, with fine detail and fast motion the most visibly affected ([note.com](https://note.com/truenorthai/n/ndb31c47d18e7?hl=en)). WAS's per-seed PSNR scores ints8 convrot higher than lower-bit quants ([WAS](https://huggingface.co/WAS/Minimax-h3_Singularity_v2_pruned)). This supports the planned int8 switch. No source measures eyes specifically.
7. **Keep `low_vram` off** on quantised bases; turning it on softens output ([Larryvrh](https://github.com/Larryvrh/ComfyUI-MiniMax-H3-Turbo)).

### 2. Burned-in Chinese text, dialogue, names, negative prompts

Ranked actions:
1. **Stop putting speech in quotes.** H3 treats double-quoted text as visible on-screen text (signs, captions, rendered verbatim, including Chinese). Spoken lines must use the dialogue tag:
   `(S1) says softly: <d>[Chinese] 我们走吧。</d>`
   Sources: [comfy prompt guide](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-prompt-guide), [comfyui-wiki](https://comfyui-wiki.com/en/tutorial/advanced/video/minimax/minimax-h3-prompt-writing). The `[Chinese]` tag comes from [colorAi Prompt-Engineer](https://github.com/colorAi/ComfyUI-Minimax-H3-Prompt-Engineer).
   - Keep the speaker ID, action and delivery outside the tags.
   - End each line with `。`/`？`/`！`; avoid ellipses, which hurt intelligibility.
   - Voice-over: write "says in an off-screen voiceover: <d>…</d>, her lips stay closed."
   - `<d>` is a special token added to the tokenizer, so the encoder needs the repo tokenizer ([MiniMax card](https://huggingface.co/MiniMaxAI/MiniMax-H3)). Check that your text-encoder loader keeps it (**unverified** for quantised or GGUF encoders).
2. **Remove character names and the "name: line" table format.** Base modes identify speakers by `(S1)`/`(S2)`, not names. Describe each person by appearance. On first appearance, define the voice: type, age, gender, on/off-screen, pitch, timbre, rate, accent. A name plus a short phrase is exactly the pattern that comes out as a subtitle (my inference from the quote rule).
3. **Write the structure in English;** only the dialogue inside `<d>` stays Chinese ([comfy guide](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-prompt-guide)). MiniMax says its hosted Context-IR, which is not open-source, serialises raw instructions into this structure and "strongly recommend[s]" replicating it.
4. **Negative prompts.**
   - Stock FL2VA and Ref2VA are CFG-distilled. The template uses `BasicGuider` at cfg 1 with no negative branch, and the official guide warns that ban lists can add the very concepts they name ([comfy guide](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-prompt-guide), [seedance](https://www.seedance.tv/blog/minimax-h3-negative-prompt-comfyui)).
   - `CFGGuider` with cfg > 1 is possible in principle (double compute), but there is no H3 evidence and it risks harder edges and unstable motion. **Unverified.**
   - The core `NAGuidance` node gives negatives on distilled models elsewhere (Flux Kontext, Krea 2); no H3 test found. **Unverified** ([NAG docs](https://docs.comfy.org/built-in-nodes/NAGuidance)).
   - Practical route: describe a clean frame positively in the shot text, e.g. "No subtitles, captions, interface elements, logos, labels, letters, or watermarks appear at any time." ([seedance](https://www.seedance.tv/blog/minimax-h3-negative-prompt-comfyui)). Sources disagree on whether such lines help.

### 3. Props on the wrong body part / prompt length

- **Length and encoder facts.** The encoder is Qwen3-VL-32B, taking hidden states from layer 50 ([MiniMax card](https://huggingface.co/MiniMaxAI/MiniMax-H3)). No token limit or truncation is documented anywhere. A 7000-character prompt field is community-reported and unverified. The main description field typically runs 350–500 English words. Nothing found measures attention to early versus late tokens.
- **I2VA template** (verbatim alignment line, [HF #47](https://huggingface.co/MiniMaxAI/MiniMax-H3/discussions/47), [teskor skill](https://github.com/teskor-hub/minimax-h3-skill/blob/main/portable-prompt.md)):
  ```
  For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.

  integrated_multimodal_description: [Shot 1] <first-frame anchor matching the image> -> action onset -> development -> result. Camera: "<motion type> + amplitude + speed" (e.g. "a slow, small-amplitude push-out"). (S1) ... <d>[Chinese] ...</d> [Shot 2] At 00:03.500, the camera cuts to ...
  overall_soundscape: <1-4 English sentences>
  non_diegetic_music: <1-2 sentences or N/A>
  ```
  Shot 1 has no timestamp; later cut times must strictly increase. Start a new shot only when subject, space, viewpoint or time changes.
- **Props (my inference from the structure rules, not tested):**
  - Drop the separate continuity line that lists props.
  - Bind each prop to its body location in a single phrase inside the first-frame anchor, e.g. "a small silver bell on a thin red cord around her left ankle."
  - Repeat that exact phrase in later shots only when the prop matters, and mention only props that are visible.
  - Let the first frame carry the appearance: describe what the image shows, without adding or redesigning details.
- **Encoder quality.** The comfy default encoder is `qwen3vl_32b_minimax_h3_nvfp4_awq`. NVFP4 is not native on Ampere, and encoder quantisation could weaken how well prompt details bind (**unverified**; worth a bf16/fp8 encoder A/B on the spare 3090s).
- **Splitting.** Shorten or split a shot when one prompt carries too many events ([seedance](https://www.seedance.tv/blog/minimax-h3-negative-prompt-comfyui)).

### 4. NSFW model and LoRA evidence

- **10Eros Max beta5** ([civarchive](https://civarchive.com/models/2851079?modelVersionId=3294059)): the best-documented option. It is a hybrid of fl2va and ref2va.
  - The creator calls the int8 TURBO file the default. Shift 12 video / 3 audio; raise audio shift to 6–10 at low step counts.
  - Samplers: er_sde/beta57 at 4–6 steps for least drift; res_multistep/simple at 6–9 for motion; LCM/simple at 6–8 for best turbo audio. Euler/simple was reported noisy.
  - Do not stack turbo LoRAs on it, and do not connect a negative prompt.
  - Latent contrast 0.85 reduces the plastic look.
  - LoRAs: Mystic V4 at **0.2–0.6** only; anatomy LoRAs at 0.2–0.6; avoid stacking generalist LoRAs, since the merge already includes them.
  - For I2V, the creator recommends ref2va mode with the image locked as start frame. For adherence: higher resolution and shorter clips.
  - Side effects reported: turbo audio produces thumping, knocking and chomping in NSFW scenes (non-turbo with about 25 steps fixes it); female-anatomy bias; T2V detail softer than I2V; one blue colour shift. No eye regressions reported.
- **DaSiWa Hybrid v4 Turbo** ([civarchive](https://civarchive.com/models/2877206)): a checkpoint covering t2va, fl2va and ref2va. Turbo: euler/simple or LCM/simple, 4 or 8 steps, shift 6–12 / 3–5. Non-turbo: res_multistep/simple, 20–25 steps, shift 10–12 / 3–5. Variants of 11.7, 15.6 and 19.5 GB (int8). No known issues or reviews posted.
- **PinkCherry**: the HF cards have no settings or technical information.
- **Not found anywhere:** Minimax_H3_Unlocked_V2.1, MysticXXX MMH3-V4 (apart from the 10Eros note on "Mystic V4"), AfterMidnight, RunningHub NSFW, kimjob. Strengths for these are **unverified**; start at 0.4–0.6 by analogy with the 10Eros advice.
- **Character swap LoRA:** not researched.

### 5. Settings for best texture on 24 GB Ampere

| Frames | 17k+5 at 24 fps; 141 is valid; trained range about 124–362 | |

**LightX2V FL2V turbo v1.2:** officially 4 steps, Euler, shift 6/3, up to 768p ([lightx2v #52](https://huggingface.co/lightx2v/Minimax-h3-Turbo/discussions/52)). v1.2 improves audio, but users report visual quality and hair worse than v1.1. If picture matters more than audio, keep v1.1 or run 8 steps ([comfyui-wiki v1.2](https://comfyui-wiki.com/en/news/2026-09-06-minimax-h3-fl2v-turbo-v1-2)). Community strength range 0.6–1.0 is **unverified**.

**LMS sharp v1.0 r64:** about 0.8 strength; 1.0 on both passes is too extreme. Guide via `MiniMaxH3AddGuide` with `frame_idx=0`; same resolution, 17k+5 length ([comfyui-wiki](https://comfyui-wiki.com/zh/news/2026-09-11-minimax-h3-sharpness-lora)). The planned Kijai rank-384 refiner split is `minimax_h3_open_regenerate_2k_refiner_rank_384_bf16.safetensors` ([Kijai](https://huggingface.co/Kijai/MiniMax-H3-experimental/tree/main/loras)).

**First frame:**
- Render the NoctQ image at the **exact canvas aspect ratio and size** (768x1344). `first_frame` is resized to the canvas **without preserving aspect ratio**, so anything off-aspect is stretched ([comfy native](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-native)). That also distorts eyes.
- Use clean, readable face edges and no occlusion or cropping of the face. Generic guides only; no source tests whether a sharper source image reduces output softness.

**Unverified overall:** NAG or CFG>1 negatives on H3, res_2s/beta57, all strengths for the unfound LoRAs, the encoder-quantisation effect, the `<d>` token surviving quantised encoders, and the prop-binding advice (inferred, not tested).
