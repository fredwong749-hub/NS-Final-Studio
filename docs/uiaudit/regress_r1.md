# 功能回退检查 r1（UIAUDIT 2026-11-01，G10 首次全站跑）

起因：项目方原话"剧本的页面你改坏了！……之前起码有前后帧，还有视频……现在你又把它给搞没了"。r1–r3 的 detect 只查"缺什么"，没有查"比以前少了什么"。

## 方法

- 基线：git `e66903c` 的 `apps/web/src`（改版前 90 个 tsx）+ `data/_archive/20261031/code/apps_web/`（UIRSI 重构时下线的 22 个文件，MANIFEST.tsv 理由都写着"单一外壳后构建不到"）+ ux4/ux5 截图。整理成 35 条"改版前能做的事"，存在 `apps/web/e2e/uiaudit/baseline_features.json`。
- 静态检查：`node regress.mjs HEAD`，列出基线里有、当前代码里已经没有的操作文字，共 276 条，原始结果在 `regress_static.json`。
- 动态检查：`node detect.mjs flows_regress.json rg2`，用真实界面打开 9 个页面 / 视图（画布、精修、工具菜单、分镜表、表格、资料清单、剧本页、人物页、成片），收集正文文字和 title。然后跑 `node regress_check.mjs rg2_detect.json`，统计时不算顶栏和步骤条里的字。
- 机器判定之后，我又逐条用代码 grep 复核，排掉误报。比如人物页的"缺图"在页头里，第一次被当成顶栏排除了。
- 判定口径：
  - **P0**：全站都没有入口。
  - **P1**：功能代码还在，但入口被藏起来，或者被挪走后原来的页面没有了。
  - **dropped**：有原话依据下线的。

## 以后每轮怎么做

- UI_CONTRACT G10 已加上 UIAUDIT 的测法。
- 每轮必跑三步：`regress.mjs` → `flows_regress.json` → `regress_check.mjs`。
- 任何改版交付前，交付方必须先跑一遍，附上"P0 = 0"。
- 基线清单只增不减。要删一条，必须在 `dropped` 里写明原话出处。
