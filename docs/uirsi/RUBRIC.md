# UIRSI 打分标准（RUBRIC）

这份标准是每一轮的客观“导演”：每轮先打分，选分最低的 2–3 项来改，改完用同样方法复测。

**分数规则**
- 每项 0–10 分，**及格线 7**。
- 整体及格要同时满足两条：总分 ≥ 总满分的 75%，且没有任何一项低于 6。

**打分依据**
- 截图：`apps/web/e2e/uirsi/shoot.mjs`，1280 / 1440 / 1920 三档宽度 × 深浅两套主题。
- 点击路径实测：脚本按顺序点击并计数；或人工按下面写的路径走一遍。
- 截图日志：横向滚动、控制台错误、非 GET 请求数。
- `npm run ds:stats`。

**原则**
- 打分写证据（截图文件名或路径步骤），不凭印象。
- 同一项前后两轮必须用同一个测法。

## 打分项

| # | 项 | 怎么测 | 0–3 | 4–6 | 7–8 | 9–10 |
|---|---|---|---|---|---|---|
| R1 | **主流程一条线**：提纲 → 剧本 → 分镜 → 资产 → 首帧 → 视频 → 审片 → 成片，每个节点都能从上一个节点直接走到 | 从顶栏出发，逐节点数到“看到这个节点的产物”要几次点击；断一处扣 2 | 有节点在界面上不存在 | 节点都有，但要靠菜单或记路由 | 每个节点 ≤2 次点击，相邻节点之间有直达链接 | 一屏看到全链位置，每个节点都标出下一步 |
| R2 | **自动填好 + 待你确认**：每个节点都显示系统自动产出的内容，闸门写明“需你确认”和下一步 | 逐节点检查三件事：①自动内容可见；②闸门标识；③确认动作就在旁边 | 自动产物要去文件夹看 | 一半节点做到 | 所有节点①②做到，③缺 ≤2 个 | 全部做到，确认动作 ≤1 次点击 |
| R3 | **找东西的时间（发现性）**：新建剧本、某角色的音色、某镜的视频提示词、上一版成片 | 4 个任务，从画布首页出发，计算点击数和是否需要用工具菜单 | 有任务找不到 | 平均 >3 次点击，或要用工具菜单 | 平均 ≤3 次，不用工具菜单 | 平均 ≤2 次，并且有快捷键 |
| R4 | **状态可见性**：在写 / 在出 / 失败 / 过期 / 等你，任何时候都能看到 | 后台在跑时，看顶栏、页面、列表是否都有进度；失败是否写明原因并给出“重试 / 返修” | 状态要刷新或去命令行看 | 有状态但没有原因或下一步 | 状态、原因、下一步都有 | 加上预计时间和花费 |
| R5 | **一致性**：术语、组件、按钮层级 | 同一个动作的叫法数量；一个区域里的主按钮数（应 ≤1）；新代码是否全部用 ds 组件 | 一屏 ≥3 个主按钮，或同义词 ≥3 个 | 局部一致 | 主流程页面一致 | 全站一致 |
| R6 | **视觉质量**：层级、对齐、留白、密度、信息优先级 | 截图逐页看：对齐网格、标题层级、留白、视频 / 图是否是主角；ds:stats 只能降不能升 | 杂乱、重叠 | 能用但拥挤 | 干净、层级清楚 | 达到竞品水准，有节奏感 |
| R7 | **空 / 错 / 载入态** | 各页断开 :8800 或旁路截一次；空数据截一次；读数据中截一次 | 白屏或英文报错 | 有文字但没有下一步 | 统一的 LoadError / Empty / Skel，写明下一步 | 加上缓存外壳和自动重连 |
| R8 | **深浅主题** | 两套主题同一页对照：对比度（正文 ≥4.5:1，说明文字 ≥3:1）、没有写死颜色 | 有看不见的字 | 个别对比度不够 | 全部达标 | 达标，并且两套主题的层级感一致 |
| R9 | **三档宽度**：1280 / 1440 / 1920 | 横向滚动 = 0；1280 下关键信息不丢；1920 下不空 | 有横向滚动或重叠 | 1280 下丢信息 | 三档都可用 | 三档都好看 |
| R10 | **资产中心** | 找角色 → 形象 → 版本 → 用在哪些镜头；新建人物；P1 人物表能否进资产中心 | — | 能查不能建 | 能查能建 | 和链条打通（P1 → P5） |
| R11 | **成片页** | 看最新成片、对比两版、知道落后几镜、确认交付 | — | 能看能比 | 落后几镜可以直达对应镜头 | 有交付闸门和交付记录 |
| R12 | **画布精修** | 单镜改提示词 → 重出 → 对比 → 定稿的点击数；参数是否集中在一处 | — | 参数分散 | ≤5 次点击 | 参数集中，≤4 次点击 |

### 任务分 T1–T7（权重最高，r14 起）

项目方原话：“UI 的技术迭代还是不太行……继续 RSI。”分数涨了但体感没跟上，说明打分要测项目方真正要做的事。

`apps/web/e2e/uirsi/tasks.mjs` 在真界面上按项目方的任务一步步点。全程只读：要花钱或写数据的那一下记为“到达提交点 / 被闸门挡住”，不真的提交。每一步都截图，同时记录：
- 点击和按键数；
- 每一步的等待时间；
- 首屏时间；
- 卡在哪里（迷路处）；
- 页面上出现的报错和空白。

| # | 任务（从哪出发） | 终点 | 目标（点击 / 秒，对照小云雀） |
|---|---|---|---|
| T1 | 新建剧本（画布） | 填好提纲，“开始自动写作”能点 | 1 / 3 |
| T2 | 看 10 集（新建剧本页） | 打开整季 → 看分镜 → 换到第 2 集，看到首帧 → 换到第 10 集 | 3 / 3 |
| T3 | 挑设定图（画布） | 某角色某套造型的候选并排显示，点开“选这张”确认框 | 3 / 3 |
| T4 | 看首帧（画布） | 全屏看图 | 1 / 2 |
| T5 | 出视频（画布某一镜） | 点到“重新出视频”（被闸门挡住就记下原因） | 2 / 3 |
| T6 | 审片打回（画布某一镜） | 打回原因框打开 | 2 / 2 |
| T7 | 看成片对比（画布） | 两版成片并排，能播放 | 2 / 3 |

**任务分**（0–10）：从 10 分开始扣：
- 比目标多点一次，扣 1.5；
- 比目标多等 1 秒，扣 1；
- 卡住，扣 5；
- 被闸门挡住，扣 1（写明原因的闸门是设计，不算迷路）；
- 每出现一个报错或空白，扣 1，最多扣 3；
- 首屏超过 3 秒，扣 2。

每轮跑两遍（深色 1440、浅色 1280），取平均。**及格线：平均 ≥ 9。**

### 技术分 K1–K5（r14 起，自动统计）

`node score.mjs --tech <net 前缀> <tasks 前缀>`，数据来自 shoot.mjs 的 `_net.json`（Resource Timing）和 tasks.mjs 的首屏时间。

| # | 项 | 计算 | 及格 |
|---|---|---|---|
| K1 | 首屏时间 | 各任务首屏时间取平均，超过 1.2 s 的部分每秒扣 3 分 | ≤ 1.5 s |
| K2 | 首屏关键路径请求数 | 主内容出来之前已发出的 /api 请求数（不含缩略图，tasks.mjs 记 `first_api`），各任务取最大值，超过 12 个的部分每个扣 0.5 分（r19 起；之前用“前 3 秒”，会把首屏之后的延后请求也算进去） | ≤ 12 |
| K3 | 慢请求 | 用时超过 4 s 的请求个数 | 0 |
| K4 | 重复请求 | 同一个 URL 被重复请求的次数 | 0 |
| K5 | 图片体积 | 大于 400 KB 的单张图片数，每页图片总量超过 3 MB 开始扣分 | 列表里的图都用缩略图 |

以下几项暂时不能自动统计，按清单人工核对：
- 状态实时性：轮询是否已合并；
- 错误恢复：接口没上线时是否显示 LoadError；
- 键盘与批量操作：快捷键表；
- 深浅主题一致：看 R17。

**权重从高到低**：任务分 T（×2）> 技术分 K > R1–R13 > 排版 R14–R17。进展页最上面放 T 和 K。

### 排版四项（项目方原话：“字的大小、depth 的大小……字体是否 wrap 得好……margin 和 padding 的设置……字的颜色、排版和间距”）

R14–R17 是**自动打分**：
- 截图工具 `shoot.mjs` 每截一张图，就在页面里跑一次 `audit.js`，按计算样式统计（只读）。
- `score.mjs` 根据统计结果换算成分数。
- 每轮都要跑。进展页显示这四项的分数变化。

| # | 项 | 自动统计（每张截图，可见的文字元素） | 换算成 0–10 |
|---|---|---|---|
| R14 | **字号与深度** | ① 字号不在 5 档 token 内（12 / 13 / 14 / 16 / 20；≥24 的标题不算）的元素数；② 阴影不在 `--sh-*` token 内的元素数（0 0 0 Npx 的描边环算边框，不算） | 10 ×（1 − ①/文字元素数）− min(3, ②/截图数) |
| R15 | **换行与截断** | ③ 溢出（内容比盒子宽，且没有截断或滚动）；④ 有省略号截断却没有悬停全文（本元素和祖先都没有 title）；⑤ 单字成行（中文换行后最后一行只剩不到 1.3 个字宽） | 10 − 2 ×（③+④+⑤）/截图数 |
| R16 | **间距** | ⑥ padding / margin / gap 不在 4px 网格上（`--sp-*`；1–2px 细线放行）的元素数 | 10 ×（1 − ⑥/文字元素数） |
| R17 | **颜色与对比** | ⑦ 文字颜色不是 `--c-*` token；⑧ 对比度不达标：正文 < 4.5:1，次要文字（`--c-text-2/3`）和大字 < 3:1；叠在图片 / 视频上的角标不算 | 10 − 100 ×（⑦+⑧）/文字元素数 |

另外记录行高：多行文字的行高 / 字号 < 1.3 的元素数（`lineTight`），只记录，暂不计分。

**满分**：R1–R17 共 170 分。
**及格**：总分 ≥ 128（75%），并且每项 ≥ 6。

> r5 之前的轮次只有 R1–R13（满分 130）。从 r5 起加入 R14–R17。
> 同一轮内用同一份 `audit.js`。r7 起，叠在画面上的角标不再算对比度（之前把图片当成了白底，属于误报）。

## 记录格式（`rounds/rN.md`）

1. 本轮分数表（每项附证据）；
2. 选中要改的项和原因；
3. 改法（文件）；
4. 改前 / 改后截图；
5. 复测分数变化；
6. 写回 `knowledge/rules/ui.yaml` 的规则。
