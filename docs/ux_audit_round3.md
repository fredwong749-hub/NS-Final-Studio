## 二、本轮新问题

**R1. 派到 gpu36 的视频渲染完后存版本失败；原始英文报错直接显示给项目方**（P0）
- 截图：produce_history_ep02.png；jobs_drawer.png；`GET /api/jobs` 的返回
- 实测数据：
  - ep02 整集出片 05:23–05:37：S3 在 gpu33·卡1 完成。S9、S10 分别在 gpu36:0、gpu36:1 渲染约 14 分钟，结束时都报 `1 validation error for Take gpu Input should be a valid integer … input_value='gpu36:0'`。
  - 05:40 又开了一轮，S1、S5 再次被派到 gpu36:0 和 gpu36:1。
  - 顶栏失败数在审查期间从 2 涨到 4。
- 问题：
  - Take.gpu 的 schema 只接受整数，而 G36 的道 id 是字符串。
  - 调度器会继续把视频派给 gpu36，每次空跑约 14 分钟。
  - 界面直接显示 pydantic 原文，还带“For further information visit http”。
- 影响：G36 加卡带来的并行收益变成负数。项目方看到的是一段英文报错，判断不了是卡坏了还是哪里出了问题。
- 建议：
  - Take.gpu 放宽为 `int | str`；或者存版本时把道 id 和 gpu 编号分成两个字段。修好之前先把 gpu36 道从视频候选里拿掉。
  - 失败原因在前端映射成中文，比如“存版本失败（系统问题，不是画面问题），已通知”，原文只放在悬停提示里。
- 代码：packages/schema/ns_schema/edits.py（Take.gpu）、services/render_router/ns_render/pipeline.py（_add_take）、services/api/ns_api/video_jobs.py、episode_produce.py；前端 v3/ProduceHistory.tsx、components/Drawer.tsx

**R2. GPU 面板里没有 gpu36；顶栏写“卡 5/5 忙”，面板只列出 gpu33 的 4 张卡**（P1）

**R4. “自动测试定稿”有 5 种写法**（P2）
- 截图：review_ep02_1600_dark.png、edit_ep02S2_1600_dark.png、produce_history_ep02.png
- 5 种写法：
  - 行格：“自动·待复审”
  - 精修大格：“自动定稿·待复审”
  - 通过按钮下面：“自动定稿·待你复审”
  - 状态胶囊：“视频是自动测试定稿，待你复审”
  - 版本条：“自动”
- “过期”同样有 4 种写法：
  - “过期·需重出”
  - “首帧已过期，需重出”
  - “重出首帧（已过期）”
  - 说明里引用的“重新生成首帧”
- 建议：在 status.ts 里定义一张“状态 → 短名 / 长名”表，所有地方都从这张表取：短名用“自动·待复审”，长名用“自动测试定稿，待你复审”。动作统一叫“重出首帧”。
