### 1.1 状态词：每类各写各的

| 资产 | 现在的状态写法 | 代码 |
|---|---|---|
| 角色底板 | 没有字段，文件名里带 rejected / superseded / 作废 等字样就算归档 | `assets.py:103` |
| 形象 / 单品 | `needs_review: bool` 加 `version: int` | `ns_schema/looks.py:56,93` |
| 场景底图 | `missing / candidate / owner_confirmed`，另有 manifest 的 `locked`；界面写“候选 · 未定稿 / 已定稿 / 项目方已确认” | `state_timeline.py:360`、`ScenesTab.tsx:17-24` |
| 资产生成记录 / 参考图 | `void{by, reason, at}`，label 写“作废候选”“候选·待复审” | `asset_edit.py:579-593` |
| 向导人物 | `confirmed / approved_by / approved_at` | `wizard.py:546` |
| 镜头版本 | `locked / active / locked_by.auto`（自动·待复审）；审片是 `unreviewed / passed / rejected`；过期靠现算 | `words.ts`、`app.py:147` |
| 预设 | `tier = preview / final`；内置的不能删 | `frame_jobs.py` |
| LoRA | gpu3 注册表 `status=accepted`；视频 LoRA 有 `license` | `render_quality.json` |

结论：没有一套共用的“草稿 / 候选 / 定稿 / 作废 / 过期”。项目方在不同页面看到的是不同的词，有时还是不同的颜色。

## 3. 新信息架构：一个“资产中心”

### 3.1 分类：6 类，角色是聚合根

```
资产中心（顶栏 ② 改名“资产”，只有这一个入口；旧资产库、人物管理并入，旧入口保留只读一段时间）
├─ 角色 ········ 人。下面挂：形象（整套）· 衣橱（服装 / 鞋 / 妆 / 甲 / 发 / 饰）· 身份参考（母版 / 四向底板 / 表情）· 音色 · 身份 LoRA
├─ 场景 ········ 地点。下面挂：子场景 / 时段 / 机位变体（底图版本链）· 空间参考
├─ 道具·产品 ···· 可以单独出现、可以被任何角色穿戴或手持的东西（首饰、鞋履产品、手机……），可挂产品 LoRA
├─ 风格 ········ 出图预设 · 视频出片方式（基底）· 附加视频 LoRA · 风格 / 色彩参考图 · 视觉圣经（只读）
├─ 声音 ········ 音色（按角色，也能从角色详情进）· 配乐（按集）· 环境声（只读剧本原文）
└─ 提示词模板 ··· 容器：立绘模板、场景底图模板、视频提示词格式模板……（文字由项目方 / 写作方写，系统只存、只引用）
```

为什么这样分：

1. **按项目方脑子里的名词分，不按存储分。** 项目方说的是“场景、声音、服装、画面、提示词”。“服装”是角色的一部分（一个人的衣橱），所以放在“角色”下面，不单独做一级；同时在总览里提供“全部衣橱单品”的跨角色视图，满足“只看衣服”。“画面”对应“风格”：预设、出片方式、风格参考。
2. **角色做聚合根。** 形象、衣橱、底板、音色、身份 LoRA 都只对一个人有意义，放进同一个详情页，能消除 A1（三页分工）和 A2（跳错页）。这和小云雀“角色 → 造型”的结构一致（`xyq_flow_full.md` 第 16、80 行）。
3. **道具·产品单独一类。** 它们会跨角色、跨场景复用，而且有自己的 LoRA（A14）。小云雀的资产面板也是“角色 · 场景 · 道具 · 素材”四个页签（`ux4/xyq/x05_assets_tab.png`）。
4. **LoRA 不单独做一级，挂在“谁的 LoRA”下面。** 身份 LoRA 挂角色，首饰 LoRA 挂道具，风格 / 视频 LoRA 挂风格。另外在“风格 → 全部 LoRA”提供一张只读的总表，合并 4 处来源，显示许可、阶段、用在哪。原因：项目方关心的是“林晚的脸 LoRA”，不是一个文件名。
5. **提示词模板单独一类，但只是容器。** 系统负责存、编号、引用、显示“哪些资产 / 镜头用了第几版模板”，不生成也不改写里面的文字。这是对“提示词管理”的系统层回应，不越过“Claude 只写系统”的边界。
6. **参考图不做一级。** 参考图永远属于某个资产（角色、形象、单品、场景、道具、风格），在该资产详情的“参考图”区里管。这样消掉了“参考图在 4 处”的问题。

### 3.2 统一卡片（所有类型共用一个组件）

```
┌───────────────────────────┐
│ [缩略图 16:9 或 3:4]       │  ← 左上角：类型胶囊（角色 / 形象 / 单品 / 场景 / 道具 / 预设 / 音色 / 模板）
│                     [定稿] │  ← 右上角：状态胶囊（颜色固定，见 3.3）
├───────────────────────────┤
│ 名称                  v3  │  ← 名称 + 当前版本号
│ 所属：林晚 · 形象 A       │  ← 所属（单品属于谁 / 子场景属于哪个场景）
│ 用在 12 集 · 87 镜        │  ← 引用计数，点开 = 反查
│ ⚠ 缺 正面底板、产品图      │  ← 缺什么（红字，最多一行，悬停看全部）
└───────────────────────────┘
```

统一字段（后端统一卡片接口返回，见第 5 节）：

| 字段 | 说明 |
|---|---|
| `id`、`type`、`name` | type 取 `character / look / item / scene / scene_variant / prop / preset / video_base / lora / voice / music / prompt_template` |
| `owner` | 所属，比如单品 → 角色，变体 → 场景，身份 LoRA → 角色 |
| `thumb` | 缩略图 |
| `status` | 统一状态，见 3.3 |
| `version`、`versions_count` | 同一个资产一条版本链 |
| `usage` | `{episodes, shots, by_layer: {episode_default, scene, shot}}` |
| `missing[]` | 缺什么，用资料闸门（PREP）同一套口径 |
| `source` | 上传 / 生成 / 剧本 / 导入 |
| `updated_at`、`updated_by` | 最后改的时间和人 |
| `tags[]` | 标签 |
| `license` | 只对 LoRA 和外部素材有意义 |

### 3.3 统一状态（5 个）和现有字段的映射

| 状态 | 含义 | 颜色 | 从现有字段怎么算（第一步不改数据，只做映射） |
|---|---|---|---|
| 草稿 | 只有文字或登记，没有图 | 灰 | 场景 `plate_status=missing`；单品 `images=[]`；形象没有 `preview_image` 和 `reference_images` |
| 候选 | 有图，没定稿 | 黄 | 场景 `candidate` 且没 locked；单品 / 形象有图，但 `needs_review=true` 或没确认；生成记录没 void |
| 定稿 | 可以拿去出片 | 绿 | 场景 `locked` 或 `owner_confirmed`；形象有 `look_confirmed`；角色有 `face_reference.approved_*`；预设是内置的或 `tier=final` |
| 作废 | 留着，不再用，默认隐藏 | 删除线灰 | `void{}`；文件名带 rejected / 作废；人物 `archived` |
| 过期 | 定稿后上游改了（参考图换了、模板换了），用它的镜头需要重出 | 橙 | 资产层：定稿之后 `refs` 或模板版本有变化；镜头层：沿用现有 `stale_reasons`，“过期·需重出”的写法照用 `words.ts STALE_SHORT` |

规则：

- 项目方确认（owner）是“定稿”的一种来源，显示成“定稿 · 项目方确认”。不另起第 6 个状态。
- “自动·待复审”只用于镜头版本，不进资产状态。

### 3.4 版本 vs 另存为新资产（解决 A6）

- 抽屉里默认“保存为新版本”：同一个资产 v1 → v2 → v3，资产 id 不变，用它的镜头标为过期，可以选择“只标过期，不重出”。
- “另存为新资产”是一个单独的二级动作，名字直接写出结果：“另存为新形象 B”“另存为新单品”。
- 版本链在详情页右栏显示：缩略图 + 时间 + 谁存的 + 来自哪次生成。

### 3.5 反查（“哪些镜头用了它”）

- 每张卡上的“用在 N 集 · M 镜”都能点开，打开反查抽屉：
  - 按集分组，每集一行镜头芯片（S1、S3–S5…）；
  - 每个芯片带两项信息：用的是哪一层（集默认 / 本场 / 本镜覆盖），这一镜首帧现在的状态（定稿 / 过期 / 没出）。
- 抽屉顶部的动作：
  - “在画布里只看这些镜头”：用现有的高亮或过滤；
  - “把这些镜头换成…”：走现有 `refs/preview` 看影响，再 `refs/apply`；改本集默认仍然要项目方本人勾选。
- 反查必须由后端按“实际编译结果”来算，包括单件替换、借用、场景覆盖（A10）。前端不再自己按出场人物去推。

### 3.6 画布 / 精修里就地引用和替换

- “本镜参考条”升级成 **“本镜资产”面板**，一行列出这一镜用到的全部资产：
  - 角色：形象，加上单件覆盖；
  - 场景：底图变体；
  - 道具；
  - 风格：预设、出片方式、LoRA；
  - 音色：每个说话人一个；
  - 用了哪个提示词模板（只显示名字和版本）。
- 每一项都显示来源层，用小角标写：集默认 / 本场 / 本镜。
- 每一项有两个动作：
  - **替换**：打开选择器。选择器就是资产中心的卡片网格，只按类型和“所属”过滤（比如只显示林晚的形象和衣橱）。选完显示影响面，再应用（沿用 RefSwitchPanel 的 ①整套 ②单件 ④借用 + 范围三选一）；
  - **打开资产 ↗**：在资产中心打开这个资产的详情，带 `?from=<shot>`。详情页顶部有“← 回到 ep02-S3”。
- 入口统一：审片行小卡、左栏资产库、本镜资产面板，打开的都是同一个替换选择器。双击一律“打开资产 ↗”，不再跳旧资产库（A2）。
- 左栏资产库增加“道具”“风格”两个页签。场景页签改成按 scene_id 读（A9）。
- 预设 / LoRA 从单镜“高级”里移出来，放进本镜资产面板的“风格”行。改它时要选范围：只这一镜 / 本集 / 全剧默认。不再有隐藏的“下一次出图用的参数”（A13）。
