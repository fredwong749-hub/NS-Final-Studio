## 〇、结论（先看这一段）

问题共 33 条：**P0 4 · P1 13 · P2 16**（D1–D33）。

1. **工作流最大的问题不是哪个按钮难点，而是“一条生产线被拆进了 4 套壳”**：
   - 新画布（审片 / 精修）；
   - v3 独立页（剧本创作、资产、模型）；
   - 旧壳（剧本导入、总览、旧资产库、人物管理、A/B、节点画布、旧版镜头行）；
   - 项目页（#/projects、#/inbox，又一套顶栏）；
   - 另外还有旧剧本对话框 #/script-chat。
   
   每套壳的顶栏、按钮、卡片、空状态、报错写法都不一样。项目方每天在 3–4 套壳之间来回跳。
2. **流程两头断了**：
   - 开头：“新建一集”在界面上没有这个动作。要走“剧本创作 → 送导入 → 整页刷新到导入页 → **再校验一次（约 1 分钟）** → 勾‘我是项目方’ → 导入 → 回画布找新集”，约 12 次点击、3 个页面、2 段等待。
   - 结尾：顶栏第 ⑤ 步“成片 · 可合成”点进去是旧的“全部集总览”。界面上**没有合成成片的按钮，也没有看成片、对比成片的地方**（前端没有调用任何 /api/post 的写接口或成片文件）。这是死胡同（P0）。
3. **顶栏步骤条 ①–⑤ 在说状态，点下去却去了不相干的地方**：
   - ①“剧本 · 7 镜待补”点进去是“剧本创作”（写新剧本的页），不是那 7 镜的缺项清单；
   - ③ 和 ④ 点下去都是同一个画布，没有按阶段过滤；
   - ⑤ 去了总览。
   
   步骤条是全站最显眼的导航，现在它是“看起来能点、点了会迷路”。
4. **视觉上已经有一套 token（theme.css），但没有组件层**：
   - 没有 Button / Tag / Card / Field 这类 React 组件，ui.tsx 只管状态。
   - 结果按钮有 3 套平行实现（.btn / .btn-mini、.v3-btn、.v3e-btn，外加十几个页面私有按钮）。
   - 标签、徽章有 70 多个类名。
   - CSS 里字号写了 25 种、圆角 25 种、阴影 58 种、高度 69 种。
   - 写死的颜色在 theme.css 以外还有 119 个 hex 和 53 个 rgba。
   - 139 个选择器在 2–4 个文件里重复定义，靠加载顺序互相覆盖（main.tsx 里有注释提醒“ux4.css 必须排在 v3.css 后面”）。
   
   “不够漂亮”的根子在这里：每一轮修一处，就多一层覆盖。
5. 理想流程（第三节）：把 4 套壳收成**一个外壳、四个地方**（剧本 / 资产 / 画布 / 成片），步骤条每一步都通到“这一步该做的事”。日常 12 个任务的总点击从约 **75 次降到约 38 次**，页面跳转从约 14 次降到 5 次，需要记住的东西从 9 项降到 2 项。

## 三、理想流程

### 3.1 信息架构：一个外壳，四个地方

```
顶栏： [剧名 ▾] [第 2 集 ▾ 进度]   ① 剧本 ─ ② 资产 ─ ③ 画面 ─ ④ 视频 ─ ⑤ 成片   [卡 · 队列]  [⚙]
                                        │        │        └── 同一个画布，按阶段过滤 ──┘      │
                                     剧本页    资产页                                    成片页
```

- **剧本**（合并剧本创作、导入、A/B、旧对话框）：左边按集列出“草稿 / 已导入”，右边写作、校验、确认导入。导入成功后直接打开新集画布。
- **资产**（合并新资产页、旧资产库、人物管理、项目向导的角色步）：顶部“本集造型确认”条；下面是角色 / 场景库。
- **画布**（审片 / 精修，不变）：步骤 ③ ④ 只是两个过滤器。“资料清单”“整集出片”“任务队列”都是这个画布上的抽屉，不另开页面。
- **成片**（新）：合成、播放、版本、对比、下载。
- **设置 ⚙**：模型与 API、快捷键、主题、旧版入口（折叠）。项目 / 新建剧放进剧名下拉。

### 4.5 组件

| 组件 | 规格 |
|---|---|
| **Button** | variant：`primary`（accent 实底，一个区域最多 1 个）· `secondary`（sunken 底 + line-2 描边）· `ghost`（透明，悬停 sunken）· `danger`（bad 描边 + bad 文字；确认弹窗里是 bad 实底）· `ok`（只给“通过”，ok 描边）。size：`sm` 28 / `md` 32 / `lg` 40，水平内边距 10 / 14 / 18，圆角 --r-m，字号 sm=13、md / lg=14。图标 16px，和文字间距 6。禁用：45% 透明 + `title` 写原因（必填）。kbd 提示：右侧 12px 等宽，30% 底 |
| **IconButton** | 28 / 32 方形，ghost 样式，必须有 aria-label |
| **Tag** | 高 20（xs）/ 24（s），水平内边距 6 / 8，圆角 --r-s；tone：neutral（sunken 底 + text-2）、accent、ok、warn、bad、busy（--c-{tone}-soft 底 + --c-{tone}-text 字），不用描边；左侧可带 6px 状态点 |
| **StatusDot** | 8px 圆点，5 色（灰 未出 · 蓝 生成中 · 黄 待你审 · 绿 已定 · 红 失败），沿用 v3 词表 |
| **Card** | raise 底，--r-l，内边距 16（紧凑 12），标题 --fs-l + 右侧次要动作；深色不加描边和阴影，浅色加 --sh-1；可选中：2px accent 描边 |
| **Section 标题** | --fs-s 600 + text-2，上 16 下 8 |
| **Field** | label --fs-s text-2 在上，控件高 32，sunken 底，--r-m，焦点 2px accent 70%；说明 12px text-2 在下；错误 bad-text |
| **Segmented / Tabs** | 胶囊分段（--r-pill，高 28，选中 raise 底 + 600）；页内标签用下划线式（2px accent），一个页面只用一种 |
| **Table** | 行高 40（紧凑 32），表头 --fs-xs 600 text-2 + 底线；数字右对齐；悬停 hover 底；选中左 2px accent；空单元写“—”，悬停写原因 |
| **Drawer** | 右侧，宽 420 / 560 两档，--sh-pop，头部 56（标题 + 关闭），底部固定动作区；Esc 关闭；同时只开一个 |

| **Popover / Menu** | --r-m，--sh-pop，项高 32，分组标题 12px text-3 |
| **Empty** | 44px 圆角图标 + 一句现状（--fs-m）+ 一句下一步（--fs-s text-2）+ 可选按钮，第 4 轮的 v3-empty 推广到全站 |
| **Loading** | 已知形状用骨架（同尺寸 sunken 块，1.2s 呼吸）；未知形状用 16px 转圈 + “正在读…”。只有这两种文案 |
| **LoadError** | warn-soft 底条：一句人话 + “重试” + 折叠“技术细节”（原始报错放这里），不再直接显示“502 Bad Gateway” |
| **Toast** | 右下，最多 3 条，成功 3 秒、错误常驻直到关闭 |

### 4.6 落地约束（防止回潮）

- 新组件放 `apps/web/src/ds/`（Button、IconButton、Tag、Card、Field、Tabs、Table、Drawer、Modal、Empty、Loading、LoadError）。
- stylelint：禁止 `#hex` / `rgb()`（theme.css 除外）、禁止 px 字号、禁止不在档位上的圆角。
- 加一个 `npm run ds:stats`，跑附录 A 的统计脚本，数字只许降不许升。

### 建议的改造顺序

1. 先改 ds/ 组件和 token（第四节），不动页面结构：把 .btn / .v3-btn / .v3e-btn 收成 Button，chip / badge 收成 Tag。这一步只换皮，风险最低，“漂亮”这一项立刻能看到变化。
